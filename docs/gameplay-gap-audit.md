# AI 自定义玩法缺口审计

更新时间：2026-08-23。此表以“AI 能否稳定生成、运行时是否真实执行、玩家能否完成一局循环”为准，不把只有类型声明或旧注释的功能算作已完成。

协议方向已冻结为严格现代格式：AI 只生成浅层 JSON + 简易公式，不再兼容旧效果字符串。`0.5.76` 保留为删除前实机基线，之后优先清除双 parser、双 adapter 和旧世界书示例，不以新增玩法字段推迟迁移完成。

## 当前可靠能力

| 系统 | AI 新输出 | 运行时与酒馆链路 |
| --- | --- | --- |
| 卡牌 | 单对象或数组形式的浅层 `effects`、`damage + hits` 多段攻击、无顺序依赖的组合对象、牌区/回合/牌型计数公式、X 费、条件、取回、牌库顶预见与抽牌堆检索、Power、弃牌触发、动态插牌；不输出重复 `description` | 共享契约先归一化并展开为同一结构化程序，多段攻击编译为已有普通伤害节点；出牌事务原子更新总数及攻击/技能数，纯核心从最新状态重算，牌区移动、顶部候选、全抽牌堆选择、唯一 ID、回合和消息快照有自动测试及实机证据 |
| 状态 | `apply/stack/tick/remove/hold` 浅层数组、层数衰减、`stun:true`；不输出重复 `description` | 状态定义统一规范化并生成含触发、衰减和上限的说明；修饰符与眩晕按持有者结算 |
| 遗物/能力 | 同级 `trigger` + 浅层 `effects`，含 `card_played`、三种牌型出牌、`on_exhaust` 消耗联动与 `passive` 修饰符；均不输出重复 `description` | 通用出牌后按牌型追加一个事件，能力先于遗物；三类消耗路径共用移动后通知管线，规则描述从同一程序生成 |
| 道具 | 浅层 `effects`、持有数量；不输出重复 `description` | 使用事务回滚；程序生成规则描述，离开战斗时数量写回 MUV |
| 敌人 | 浅层行动/能力/欲望效果，随机、权重、顺序、顺序后权重；机械对象不输出重复 `description` | 程序生成行动与欲望效果说明；名称、权重、配置与所有效果启动前预检，构筑和危险级生成生命/伤害预算 |
| 结算 | 胜/负/Event 终止、战斗总结、刷新恢复 | 确认离开前保留终态；离开时原子写回 HP/欲望/道具并清理临时能力、状态、敌人和快照 |
| 成长 | 经验、连续升级、偶数等级删卡次数 | 前端原子结算；AI 只增加经验，不能直接改等级 |
| 奖励 | 卡牌/遗物/道具候选与选择上限 | 程序按普通/精英/Boss 给出候选、稀有度和经验预算；领取事务原子化，坏内容不会进入永久卡组 |
| 远征（可选） | 玩家主动开启后，程序生成当前路线；AI 只生成当前节点内容 | 默认普通 AI 剧情不创建 `run`；开启后支持 3 Act、战斗/精英/事件/营火/商店/Boss、金币、胜负与刷新恢复，完整地图不进提示词 |
| 升级 | AI 只输出所选单卡的短补丁 | 程序限制字段、校验公式/状态引用并原子替换永久牌组 |
| 叙事 UI | 原生正文、普通/战斗选项、末尾状态栏、战斗引导后 iframe | 新协议不再要求正文包裹标签；普通与战斗正则互斥 |

当前 `0.5.83` 世界书共 `12,850 o200k_base token`，首轮激活 `9,282`，普通回合常驻 `3,756`；初始内容修复请求 43、战斗场景修复请求 33、带构筑/敌人预算的战斗路线消息 138、带有界连续性摘要的事件路线消息 128。远征改为可选没有增加 AI 字段或复杂卡牌输出长度。

跨宿主内容包现在在 `BattleRequest` 边界统一校验：现代 `effects`、内部程序策略、状态引用、稳定 ID、敌人行动和 MUV 嵌套数组包装只维护一份核心契约。`0.5.77` 的网站、服务、Mod 与酒馆接受同一现代输入失败语义。

## 本轮已封闭

- 构筑不再只能响应任意 `card_played`。Attack/Skill/Power 各自有一个共享牌型事件，AI 只替换同级枚举值；核心返回有序事件列表，Tavern 不复制牌型分支。真实酒馆用非交换的格挡公式验证了通用事件先、牌型事件后以及每个事件内能力先、遗物后，Power 自动消耗、`on_exhaust` 和刷新快照也在同一链路通过。

- 消耗构筑不再只能读取消耗堆数量。`on_exhaust` 由打出后消耗、Power、空灵和效果选择消耗共用的唯一管线发出；牌先移动，随后能力和遗物按固定顺序触发，失败由既有事务隔离。真实酒馆已验证消耗牌触发遗物格挡，并与消耗堆公式、消息快照同时保持一致。
- 抽牌/回洗构筑使用同一个生命周期入口：普通抽牌逐张发出 `on_draw`，弃牌堆回洗发出一次 `on_shuffle`，起始手牌不伪造抽牌事件；内容契约拒绝这两个触发器再次抽牌。核心 reducer 已覆盖“抽 -> 回洗 -> 抽”和满手牌停止顺序；真实酒馆已验证能力先于遗物、回洗只触发一次、MUV 快照和刷新恢复一致。
- 牌区取回已进入正式链路：AI 只写 `recover/from/pick`，弃牌堆和消耗堆可选择回手，不增加事件嵌套或 `on_draw` 伪触发；所有需要选牌的现代操作共用 `CardSystem` 选择入口。真实酒馆已分别验证弃牌堆/消耗堆候选过滤、原卡移动、手牌上限、消息快照和刷新恢复，格挡探针确认没有伪造抽牌事件。
- 牌库顶决策不再只能靠立即抽牌。AI 只写 `scry:N`；纯核心限制候选为实际牌库顶并保持未弃卡顺序，Tavern 复用同一选牌弹窗的 0-N 模式。真实酒馆已验证从 3 张中只弃 1 张、官方快照、刷新恢复和 `on_draw/on_discard` 零伪触发。
- 抽牌堆定向检索不要求 AI 生成筛选器或嵌套选择器。AI 只写 `seek:N`；内部复用到手牌命令、共享牌区 reducer 和统一选牌弹窗，真实酒馆已验证整个抽牌堆候选、原卡移动、手牌上限、官方快照、刷新恢复和 `on_draw` 零伪触发。
- 回合成长和攻击/技能连击不再需要 AI 模拟计数状态。`turn_number` 与三种本回合出牌计数直接进入现有公式；当前牌在效果执行前由出牌事务计入，失败则随事务回滚，下一玩家回合由统一状态转换归零。真实酒馆与消息快照共同验证了第一回合 `4/2/2`、第二回合 `0/0/0`。
- AI 不再为常见多段攻击重复三个伤害对象，也不需要嵌套新节点；单个 `damage + hits` 对象在唯一编译器中展开，每击继续使用既有格挡、伤害事件和触发事务。手牌、抽牌堆、弃牌堆与消耗堆数量使用现有公式入口，Tavern 适配层没有第二个执行器。真实酒馆已验证 5 格挡被 `3×3` 逐击消耗后只损失 4 生命，并验证 1 张消耗牌按公式提供 4 格挡。
- 战斗消息不再只能显示原始校验错误后要求用户重试。原始 MUV 在会话初始化前经过同一预检；失败时 fish 显示由纯核心生成的安全路径/错误码摘要和唯一修复按钮，条件世界书只重建当前敌人及必要临时状态。请求、UI 与测试均禁止回显敌人名、行动名、公式和底层错误文本；合法战斗仍直接进入玩家回合。
- 首轮路线不再用“存在一个卡牌 ID”作为可玩依据。`playerContentReadiness.ts` 复用唯一现代内容契约和机械分析，在 floor 0 同时检查字段、牌组数量、可出牌、胜利/防御、遗物、道具、欲望满溢、生命/欲望与成长数据；失败时路线按钮替换为“请求 AI 修复”。短请求不回显不可信字段值，完整规则由单独的 `[战斗内容修复]` 条目按需激活，修复后在下一消息重新经过同一门禁。
- `runPacing.ts` 单点维护 Act、层数、节点种类和同类节点次数对应的节奏、事件代价、商店层级与奖励档位；`runPrompt.ts` 单点维护路线/选项 marker 顺序，`worldContinuity.ts` 只从已有 MUV 的地点、威胁和追踪 NPC 读取最多一行短摘要。Tavern 仅在事件路线附加连续性，战斗/商店才构建一次牌组上下文。AI 只收到短自然语言提示，`run` 存档和 AI JSON 都没有增加字段。同机制内容允许复用，只要求叙事身份与此前同类节点区分。
- 真实 Tavern 校准工具已复用 HTTP 边界和 `contentAnalysis`；多份旧/现代样本确认触发权重问题只存在于预算分析，不需要复制执行器或修改卡牌语义。现代根触发、外层生命周期与单项 `on` 覆盖已有回归门禁，并在 `魔法少女世界128.png` 完成真实回合及刷新恢复。
- `compactEffectContract.ts` 单点维护单对象/数组归一化、组合展开顺序与操作元数据。编译、显示、内容分析、预检、奖励、动态状态、升级和 Schema 不再持有第二套组合规则；真实酒馆已覆盖对象格式的组合卡、状态、敌人行动、欲望效果和刷新恢复。
- `ContentPack` 已把全部战斗内容放入宿主无关输入，`BattleRequest/BattleResult` 已真实接入预检、session 指纹、运行时转换和 MUV/路线结算，并非只存在于类型层。
- `contentContract.ts` 已成为 `BattleRequest` 的跨宿主输入门禁；Tavern UI 不复制效果语法或核心策略，现代效果和状态引用只在核心校验一次。
- 战斗 seed 与 cursor 已写入消息快照；洗牌、回洗、随机插入/选择/弃牌和敌人行动不再读取全局随机。刷新重放不会从新的随机支线继续。
- AI 不再自行估算敌人强度。程序从当前牌组生成一行构筑预算，再根据危险级给出敌人 HP/常规行动区间；额外提示只在战斗节点激活。
- 奖励数量、稀有度、经验和商店候选数量由程序按节点给出扁平预算；商店价格完全由程序确定，AI 只负责主题与具体效果。
- 卡牌描述由已验证规则生成，公式、条件、触发器、弃牌效果和关键词使用同一来源；战斗状态与奖励自带状态通过定义显示中文名称。营火改变规则时会重新生成说明。
- 状态、遗物、道具、能力、敌方行动和欲望效果同样从现代规则生成权威说明，不再猜测字符串效果。
- 奖励候选可按需携带一个新状态定义；程序只在该候选被选择时原子注册，并剥离永久内容中的辅助字段。路线方向增加短机制侧重，进一步约束事件、商店和战斗只换名称不换机制。
- 奖励与商店允许不同稳定 ID 的同机制内容共存：叙事身份、来源和设定本身具有价值。程序只阻止会破坏数据的重复 ID 冲突、同 ID 遗物重复持有、非法规则和未知状态，不保存候选历史，也不把额外分析塞给 AI。
- 战后奖励与商店由程序给出牌组短板、已有主轴和三张候选的分工；`roles` 会附带短方向（如 `补短板(防御)`、`强联动(状态:ember_mark)`），AI 不再自行通读整副牌做重复构筑分析。开局地点/NPC 与入侵类型规则只激活一次。
- 非战斗事件的 `hp/gold` 代价与路线在纯核心中原子结算；未知字段、数值字符串、过期节点和非失败致死不会留下半结算。
- 最新消息在 `battle.cards` 为空时只显示“等待起始牌组”，不会允许玩家绕过角色创建进入空牌组远征；历史楼层、待领取奖励和事件选择仍保持可读/可结算。事件路线只附有界的地点/威胁/追踪 NPC 摘要，不复制完整世界变量，其他节点复用普通变量上下文。
- 角色创建只发送一行浅层 profile JSON 和稳定的 `[开始游戏]` 触发标记；AI 仍负责正文与 `<UpdateVariable>`，不再收到重复的身份长描述或未接入的旧 `<CharacterProfile>` 模板。长期世界连续性复用现有 `status.location`、`factions` 和 `npcs`，不新增第二份记忆变量。
- 能力/状态触发器 ID、可注册 AST 子集和状态所有权事件映射由 `battleTriggers.ts` 单点维护；`triggerDefinitionRuntime.ts` 单点维护能力与遗物的定义匹配、顺序和递归门禁，`declarativeModifierRuntime.ts` 单点维护 passive/hold 修饰符。结构门禁禁止预检、执行器或 UI 再声明第二份触发器全集、定义筛选器或修饰符解析器。
- 出牌支付由纯核心两阶段事务负责：选择前准备，弃牌触发完成后从最新手牌和能量提交，并核验实际弃牌 ID。真实酒馆已覆盖弃牌同时治疗、生成牌、触发能力/遗物及刷新恢复。
- 战斗开始与“玩家结束 -> 敌人 -> 下一玩家”的完整步骤顺序、终态短路和敌人行动分支由 `battleTurnFlow.ts` 单点维护；属性/状态变化对应的能力与遗物通知由 `battleEventDispatch.ts` 单点维护。真实酒馆已覆盖眩晕和正常行动两条分支，均无重复触发。
- 现代结构化程序的顺序、条件与公式由 `effectCommandRuntime.ts` 单点维护；每条命令执行后重读最新状态。卡牌、Power、遗物、道具、能力、状态、敌人、欲望和动态卡牌均走同一入口，旧字符串入口已删除。
- 构筑预算、构筑建议和敌人异常诊断由 `contentAnalysis.ts` 单点提取机械特征；条件、延迟触发、生成牌和减费不会再被不同模块重复扫描或误报为确定伤害。统一分析只改变程序侧估值，不增加 AI 输出字段。
- 胜利、失败、Event 终止、快照终态恢复和双方同时死亡优先级由 `battleTerminal.ts` 维护，战后提示由 `battleEndPrompt.ts` 生成；MUV 确认结算只处理规范 `stat_data.battle`。三类终态和清理均有自动与实机回归。
- `battleSessionCoordinator.ts` 统一拥有开战、出牌、道具和结束回合的动作互斥、外层事务、回滚及终态短路；fish 只实现选择、动画、日志、牌区和效果副作用端口。`ReferenceBattleSessionHost` 已证明外部宿主无需复制酒馆事务代码。
- 能力注册只保留 `registerAbility` 类型化入口；变量、层数和公式只由纯核心解析，结构门禁防止已删除的 parser、host 和同义包装重新出现。

## 已有运行时但不再教 AI

- 旧 `ME/OP/ALL` 效果字符串、旧条件括号、旧动态插牌字符串和别名已删除。
- 内部 `mwg.effect/v1` AST 和 `spec/op/steps` 供独立后端、Schema 和适配器使用，AI 不输出。
- `ALL` 效果在新格式中拆为 `self` 与 `opponent` 两项，减少目标歧义。
- 直接修改最大生命/最大欲望等永久属性继续走 MUV 剧情更新，不放进战斗效果。

## 0.5.41 已封闭的预算联动缺口

- 构筑预算的基线现在使用真实玩家 `hp/maxHp`；低生命条件公式会随当前生命改变期望值，不再固定按半血或满血代表状态计算。
- 卡牌、当前状态、被动遗物/能力和玩家欲望效果在同一个六场景采样中联动；状态层数公式和 hold 修饰符可以共同影响同一张卡。
- 没有对应基础效果的加法型修饰符不再产生攻击、防御或恢复收益；AI 仍只接收原来的扁平预算行。
- 新增的 `min/max` 仅供程序审计和后续长期校准使用，不写入 MUV、不进入正文状态栏、不改变实时战斗执行。

## 0.5.36 已封闭的预算缺口

- 动态公式/条件内容现在通过 `analyzeContentScenarioRange()` 使用同一个结构化效果执行入口做固定场景采样；构筑摘要使用加权期望值，敌人压力诊断使用观察到的最大估计。
- 单个固定数值定义不走额外场景采样；整套构筑统一使用场景，以确保卡牌、状态和遗物联动不会被拆开估算。
- 场景范围是程序内部诊断，不增加 AI 字段、不写入 MUV、不改变真实战斗实时公式。

## 0.5.37 已封闭的校验去重缺口

- 现代 JSON、效果策略、状态引用、稳定 ID 和非法数组条目现在只经过 `contentContract`；fish 不再复制现代策略表。
- fish 只保留酒馆结构、数值和可玩性诊断；效果语法完全交给现代核心契约。

## 杀戮尖塔式完整循环的取舍

默认循环是普通 AI 角色扮演正文 + Option + 状态栏，需要战斗时沿用既有战斗入口，不自动出现路线、营火、商店或 Boss。

玩家主动开启远征后的可选循环是：程序路线选择 -> AI 生成当前节点 -> 战斗或事件 -> 终态/经验/金币 -> 奖励 -> 营火升级、商店或下一节点 -> Boss -> 跨 Act -> 最终胜负。它不保存完整地图，而是用种子确定性生成当前路线窗口，以较低存档和提示开销保留 roguelike 决策。

`RunState`、节点节奏、卡牌升级、内容包、跨宿主内容契约、战斗输入/输出契约、卡牌规则描述、seed 随机流、触发器目录与定义运行时、声明式修饰符、状态生命周期、两阶段出牌支付、完整回合协议、事件分派、结构化效果命令、终态与会话协调已经进入纯核心。下一阶段聚焦公式/状态/遗物联动的预算校准，以及长期世界推进。网站、酒馆和 Mod 各自只负责适配存储、选择 UI、动画、日志和领域命令副作用；卡牌处理和战斗后端继续禁止读取 DOM、MUV 或 Tavern Helper，也禁止在适配层重复实现核心规则。
