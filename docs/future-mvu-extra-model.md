# MVU 独立模型后续配置

`0.5.93` 已完成 MVU 额外模型主线：角色卡默认使用“额外模型解析”和自动请求，世界书只发送 `[mvu_update]` 条目。兼容假流式和默认主连接由卡内加载器初始化到全局设置，不写入角色级覆盖。

本文件只记录后续可选能力，不属于角色卡默认配置：

- 玩家可在 MVU 面板把模型来源改为自定义 API 方案，让变量模型与剧情模型使用不同 URL、模型或采样参数。
- API Key 只能保存在用户自己的酒馆设置中，不能写进角色卡、仓库或世界书。
- 自定义后端必须先单独验证一次请求成功；`502/AbortError` 属于后端连接失败，重复请求不会被角色卡转换为有效更新。
- 独立模型仍只负责变量候选，不能接管剧情、卡牌执行器、奖励事务或战斗规则。
- 自定义模型输出继续遵守 `_.set/_.assign/_.remove/_.add` 协议，不得恢复 XML 树形命令。

模型职责和当前默认配置见 `docs/mvu-worldbook-boundary.md`。
# 后续：远征专用激活与按需额外模型

普通剧情与远征必须保持两条清晰边界：普通剧情由首次设置之外的日常对话自由推进，用户输入不应被模式按钮或战斗开关限制；远征模式则在首次设置阶段选择后，激活远征专用世界书与输出协议。

远征重构暂不在本次修复实现。后续设计要求：

- 首次设置写入模式，模式选择决定是否启用远征世界书，而不是把 `[远征模式]` 当成每轮用户输入限制。
- 用户的自然语言输入在两种模式都保持自由；战斗是否发生由剧情模型上下文和剧情推进决定。
- 只有剧情产生需要持久化变量、战斗注册或远征节点结算的交接标记时，才请求 MVU 额外模型；不能靠用户输入一个“战斗按钮”强行触发。
- 该按需请求机制需要酒馆助手/MagVarUpdate 提供可观测的显式请求 API 或卡内可靠的交接事件，不能用正则猜测普通文本。
