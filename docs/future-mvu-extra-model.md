# MVU 额外模型后续任务

状态：**后续任务，不属于 0.5.86 主线或当前验收范围**。

## 已确认事实

- 当前角色卡固定使用 MagVarUpdate `v0.181.0`。仓库根目录的 `mvu.js` 只监听生成与消息事件、解析 `<UpdateVariable>` 并写回楼层，没有发起额外模型请求。
- MagVarUpdate 当前 `master/beta` 已实现“额外模型解析”。它能在剧情回复后调用酒馆助手 `generate/generateRaw`，把第二次生成的变量命令追加到当前 AI 楼层，再走同一 MVU 更新链。
- 酒馆助手 `4.9.3` 的 `generate/generateRaw` 支持静默并发、命名预设、独立 `custom_api` URL/Key/模型、代理预设、工具调用和 JSON Schema。使用当前酒馆连接时无需第二套 API；使用真正独立模型时必须由玩家在本机配置凭据，凭据不能写入角色卡。
- 新版 MVU 以世界书 comment 标记区分提示词：`[mvu_plot]` 只发剧情轮次，`[mvu_update]` 参与变量轮次；禁用的 `[config_override]` 条目可让角色卡覆盖“随 AI 输出/额外模型解析”、自动请求和世界书过滤规则。

## 后续实施边界

1. 先在独立分支升级 MVU，不覆盖 `0.5.86 + v0.181.0` 已通过的最终卡。
2. 审计全部世界书条目并显式分类 `[mvu_plot]`、`[mvu_update]`；不能仅安装新版脚本后直接启用额外解析。
3. 默认仍需即插即玩：未配置独立 API 时可继续使用当前酒馆模型，或保持“随 AI 输出”。
4. 独立模型只负责变量候选，不接管卡牌/战斗核心规则，也不绕过现有奖励校验器和原子事务。
5. 分别实测聊天消息、工具调用和格式化输出；官方 DeepSeek v4 类渠道使用格式化输出时需满足对应 Tavern Helper 最低版本和自定义来源限制。
6. 回归首轮初始化、普通剧情、普通战斗、战后奖励、Option 续写、重 Roll、刷新恢复和旧聊天的明确版本边界，再决定是否成为默认模式。

## 本阶段不做

- 不把 `[mvu_plot]`、`[mvu_update]` 或 `[config_override]` 加入 `0.5.86` 世界书。
- 不替换当前角色卡内的 MUV 脚本。
- 不保存或分发任何 API Key。
- 不用额外模型升级延后当前主线收口。
