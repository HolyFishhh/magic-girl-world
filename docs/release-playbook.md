## 开发保存与发布来源

2026-09-18 用户已长期授权后续更新使用 Git 保存。每个完成并验证的任务或独立阶段及时提交源码、配置、测试与文档，并在交付说明中提供提交号；尚未完成的检查必须明确记录。只提交本任务及必要依赖，不混入无关改动、密钥、玩家存档和临时证据。日常本地提交不等于推送、安装或正式发布，这些动作按对应任务已有授权执行。

正式发布必须能够从已提交的源码及锁定依赖重建。先保存完整构建输入，再从该提交的隔离快照构建、验证并提交产物；记录源码提交、最终发布提交及产物哈希。角色卡、扩展、世界书和公开下载文件必须属于同一次验证，不再仅提交产物和版本号而遗漏构建依赖。

## 下一版本的兼容清理

项目以最新版本内容为目标。1.0.2 之后的下一版本要清理只服务旧角色卡、旧扩展、旧存档和旧 DSL 的兼容入口、迁移、字段别名与兜底，不默认维护历史协议。

清理以最新正式入口的依赖为依据，同步收敛 Prompt、Schema、解析、校验/修复、执行、存档和 UI；验证最新内容从生成到保存恢复的完整链路。当前支持的浏览器和模型接口适配不因这项历史版本清理而直接移除。更新日志明确停止支持的范围和必要的新开局要求，保留玩家原数据。

## 更新记录原则

- 新条目必须覆盖上次正式发布之后已经合入的全部用户可见变化，包括其他任务或其他协作者完成的内容。
- 只写玩家现在能够导入、看到或实际游玩的内容，不写源码结构、内部协议、测试实现、尚未完成的工作或未来规划。
- 新机制用玩家能理解的玩法和可构筑流派描述；修复项按体验归类，不罗列内部字段名与函数名。
- 每次发布后把“从上次发布到本次发布”的完整新条目原样交给用户。
- 角色卡正式版本从 `1.0` 起按语义化版本递增，并在玩家更新日志中保留完整历史。

## 正式发布清单

1. 核对主仓库自上次发布以来的所有已完成改动，并更新 `docs/player-release-notes.md`；确认源码、配置、测试及构建依赖均已用 Git 保存。
2. 更新 `release.config.json`、README 与角色显示名，确保新版本不会复用旧卡缓存。
3. 完成类型检查、机制测试、界面构建、扩展构建、角色运行时导出、PNG 写入和卡内契约验证。
4. 检查最终 PNG 中的版本、显示名、世界书、正则、角色脚本和设计辅助标记。
5. 保存产物与源码提交的对应记录，提交并推送主项目。
6. 将最终 `魔法少女世界.png` 同步到卡图仓库的 `cards/魔法少女世界.png`，同时同步 `cards/魔法少女世界版本更新记录.md`；这是网页映射实际使用的发布位置。
7. 提交并推送卡图仓库，确认公开链接仍可访问。
8. 向用户提供版本号、两个提交、公开卡图链接、本次完整玩家更新条目和验证结果。

在已授权的正式发布任务中，配套扩展内容或版本发生变化时，必须同时提交主项目、同步并推送远端 `extension` 分支，不等待重复许可。发布后必须读取远端 `manifest.json`，确认版本与本地一致。普通开发保存或纯文档提交不自动触发扩展发布。
