# 魔法少女世界发布文档

这份文档是每次正式发布必须参考的长期清单。玩家可见的完整版本历史以 `docs/player-release-notes.md` 为唯一来源；单次论坛发布稿从该文件复制，不单独改写历史。

## 更新记录原则

- 新条目必须覆盖上次正式发布之后已经合入的全部用户可见变化，包括其他任务或其他协作者完成的内容。
- 只写玩家现在能够导入、看到或实际游玩的内容，不写源码结构、内部协议、测试实现、尚未完成的工作或未来规划。
- 新机制用玩家能理解的玩法和可构筑流派描述；修复项按体验归类，不罗列内部字段名与函数名。
- 每次发布后把“从上次发布到本次发布”的完整新条目原样交给用户。
- 角色卡内部版本使用 `0.x.x`；面向玩家的更新阶段使用 `beta0.x.x`。两者在本次发布快照中明确对应。

## 正式发布清单

1. 核对主仓库自上次发布以来的所有已完成改动，并更新 `docs/player-release-notes.md`。
2. 更新 `release.config.json`、README 与角色显示名，确保新版本不会复用旧卡缓存。
3. 完成类型检查、机制测试、界面构建、扩展构建、角色运行时导出、PNG 写入和卡内契约验证。
4. 检查最终 PNG 中的版本、显示名、世界书、正则、角色脚本和设计辅助标记。
5. 提交并推送主项目。
6. 将最终 `魔法少女世界.png` 同步到卡图仓库根目录和 `cards/魔法少女世界.png`，同时同步玩家版本记录。
7. 提交并推送卡图仓库，确认公开链接仍可访问。
8. 向用户提供版本号、两个提交、公开卡图链接、本次完整玩家更新条目和验证结果。

配套扩展采用持续发布：只要扩展内容或版本发生变化，就在同一次任务中提交主项目、同步并推送远端 `extension` 分支，不等待额外许可。发布后必须读取远端 `manifest.json`，确认版本与本地一致。
