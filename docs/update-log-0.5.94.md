# 0.5.94 更新记录

## 开始页

- 开始页改为两阶段界面：默认只显示“剧情模式”和“爬塔模式”两个入口，剧情模式点击后才展开详细设定。
- “远征模式”统一改名为“爬塔模式”，本版本暂不可点击，保留为后续独立玩法入口。
- 剧情设定分为角色、世界、剧情、卡牌、偏好五页，保留白木市的阵营、身份、城市和地点预设，并增加世界观、剧情方向、叙事节奏、卡牌体系、机制偏好和内容边界等自由输入。
- 预设只服务前端选择；提交给 AI 的仍是一行浅层 JSON，且只写实际填写的字段，不发送界面说明或深层结构。
- UI 延续暖白少女日记风格，去掉暗色主题和大面积渐变，针对手机与桌面分别收窄布局。

## MVU 两阶段交接

- 第二轮 MVU 常态激活精简的“卡牌常驻规范”，每轮都保留稳定 ID、浅层 `effects`、注册/移除和交接标记约束；完整战斗内容规范仍只在初始化、获得内容、战斗与奖励场景激活，避免普通回合承担整份长规则。
- 首次开场增加 `<CHARACTER_INIT_PENDING>` 交接标记。第一阶段只写剧情，第二阶段 MVU 在当前助手楼层稳定命中初始化规则，并一次性建立状态、卡组、遗物、道具、欲望效果、等级、势力和重要 NPC。
- 明确把“首轮只更新时间与地点”判为初始化失败；已有可玩卡组时禁止重复初始化。
- 普通剧情增加 `<CONTENT_PENDING>` 交接：只有正文已经明确获得、学会或永久失去卡牌、遗物、战斗道具或能力时才触发，第二阶段据此落实结构化变量。
- 两个内部标记由酒馆正则与状态栏一起消费，不要求用户输入固定命令，也不会让剧情模型直接输出变量或公式。

## 兼容与验证

- 开始页仍只在首条消息楼层挂载，后续楼层沿用最近三层状态栏策略。
- 保持 `SillyTavern + 酒馆助手 + MVU` 角色卡即插即用链路；发布卡使用全新版本名称，避免同名旧卡的本地缓存污染。
