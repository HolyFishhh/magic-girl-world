# 战斗机制补全路线图

更新时间：2026-08-29  
依据：[《杀戮尖塔 1/2》机制覆盖评估](./杀戮尖塔机制覆盖评估-source.md)  
用途：记录当前项目尚未实现或仅部分实现的通用机制。每项必须同时完成数据契约、运行时、界面说明、AI 生成规范、存档恢复和自动测试，才可以勾选。

当前状态：P0–P3（多玩家除外）已完成并通过统一验收；多玩家继续作为远期事项暂缓。

## 已完成基础

- [x] 修改战斗卡牌的伤害、格挡、欲望和状态层数，支持加、减、乘、除。
- [x] 支持手牌、抽牌堆、弃牌堆，以及三者合并范围。
- [x] 支持随机、手选、最左、最右和全部选择。
- [x] 卡牌数值修改不影响 `hits`。
- [x] 支持每回合前 N 张或所有牌额外完整结算。
- [x] 支持每回合前 N 张或所有牌免费打出。
- [x] Replay 多来源叠加、只支付一次费用、最后统一移动卡牌。
- [x] 免费 X 费牌按使用 0 能量结算。

## P0：先补底层模型

这些项目是后续所有复杂卡牌的共同依赖，应优先完成。

### 卡牌身份与生命周期

- [x] 分离卡牌模板、整局牌组实例、战斗实例和临时生成副本。
- [x] 为四个层级定义稳定 ID、来源和继承关系。
- [x] 明确复制时是否继承升级、永久成长、本场修正、临时费用、附魔和负面修饰。
- [x] 明确变形、删除和战斗结束时各层级如何写回或丢弃。

完成标准：同名卡的一个实例发生变化时，不会误改其他实例；需要影响同名卡或未来副本时，必须通过显式模板组规则完成。

### 统一卡牌选择器

- [x] 增加消耗堆选择。
- [x] 增加抽牌堆顶部、底部、前 N 张和后 N 张。
- [x] 增加卡牌类型、费用、标签、稀有度、来源、升级状态过滤。
- [x] 增加同名卡、同模板卡和当前实例的明确区分。
- [x] 支持跨牌区选择时保留稳定顺序。
- [x] 为无合法目标、取消选择、目标数量不足定义统一结果。

完成标准：所有牌区操作共用一个选择器，不再为某张牌或某种机制新增专用选择代码。

### 通用卡牌补丁与作用域

- [x] 支持“本次结算、本回合、直到打出、本场战斗、整局、永久”六类持续时间。
- [x] 支持只修改当前实例、同模板实例、满足过滤条件的卡牌或未来副本。
- [x] 支持给卡牌动态增加或移除 Retain、Exhaust、Ethereal、Innate、Replay 等关键词。
- [x] 补丁记录来源、创建时间、移除条件和优先级。
- [x] 战斗结束与存档恢复时正确清理或保留补丁。

完成标准：数值成长、关键词变化、费用变化和未来的附魔/负面修饰都使用同一套补丁系统。

### 事件来源、原因与阶段

- [x] 弃牌区分主动选择、随机效果、回合清理、占卜、变形和其他牌区移动。
- [x] 伤害区分攻击伤害、效果伤害、直接失去生命、反伤、持续伤害和处决。
- [x] 记录伤害来源、原始值、格挡吸收、最终生命损失和击杀来源。
- [x] 明确抽牌、自动打出、Replay、消耗和卡牌移动的前后阶段。
- [x] 建立统一递归深度与重复触发保护。

完成标准：触发器可以准确声明“由什么原因、在什么阶段发生时触发”，不再依赖模糊的卡牌离开手牌或生命发生变化。

### 历史计数器

- [x] 支持本回合、本场战斗、整局、单卡实例和全队作用域。
- [x] 支持第一张、第 N 张、每 N 张及累计次数。
- [x] 支持按卡牌类型、事件原因、伤害类型和来源过滤。
- [x] 支持读取上一张牌、最近一次伤害和实际生命损失。
- [x] 存档恢复后保持确定性，不重复计算已发生事件。

完成标准：所有“第一次”“每若干次”“本回合已经……”机制都使用统一计数器。

## P1：覆盖《杀戮尖塔 1》主要卡牌语义

### 完整牌区事务

- [x] 支持把卡放到抽牌堆顶部或底部。
- [x] 支持按顺序移动多张牌，并在洗牌后保持确定性。
- [x] 支持自动打出、从非手牌区域打出和结算后的目标牌区替换。
- [x] 支持原子化生成、复制、回收、消耗、移除和变形。
- [x] 失败时完整回滚费用、牌区、触发器和日志。

### 生成、复制、升级、变形与永久成长

- [x] 通用卡牌变形，不依赖预设卡名。
- [x] 战斗内升级、整局永久升级和可重复升级。
- [x] 击杀、打出或满足条件后永久增加卡牌数值。
- [x] 复制时按规则选择继承哪些补丁。
- [x] 同模板卡跨所有牌区共同成长。

### 动态费用与 X 费

- [x] 费用变化支持本回合、本场、直到打出和永久作用域。
- [x] 支持抽到时重算、留在手牌时变化和打出后恢复。
- [x] 支持增加费用、设定费用和费用下限/上限。
- [x] 支持提高 X 值、额外支付和读取实际支付资源。
- [x] 明确免费打出、费用变为 0 和不消耗资源的区别。

### 表达式、条件与选择分支

- [x] 增加卡牌集合统计、状态集合和历史事件引用。
- [x] 增加安全的 `min/max/floor/ceil` 等数值原语。
- [x] 支持敌方意图、唯一牌、牌堆为空、上一张牌类型等条件。
- [x] 支持玩家从多个可执行效果中选择一个。
- [x] 支持引用最近一次实际伤害、治疗和消耗资源。

### 延迟与预约效果

- [x] 下回合触发。
- [x] 若干回合后触发。
- [x] 持续若干回合后移除。
- [x] 延迟死亡、延迟爆发和未来牌区操作。
- [x] 回合跳过或额外回合时仍保持正确顺序。

### 类型化伤害、生命损失与 Fatal

- [x] 可格挡攻击伤害。
- [x] 非攻击效果伤害。
- [x] 无视格挡的直接生命损失。
- [x] 反伤、吸血和按实际生命损失计算的后续效果。
- [x] 击杀/Fatal 携带来源，并可排除不应触发的目标类型。

### 通用规则替换

- [x] 不在回合结束弃牌。
- [x] 保留格挡。
- [x] 禁止或限制抽牌、格挡、获得能量、打出特定卡牌。
- [x] 改变卡牌最终去向。
- [x] 让原本不可打出的牌在满足条件时可以打出。

### 特殊战斗容器

- [x] 姿态：互斥状态、进入/退出事件和资源联动。
- [x] Orb：有序槽位、被动效果、主动激发和独立内部数值。
- [x] 额外回合和强制结束回合。
- [x] 多敌人实体与 ALL、随机、最低生命、指定目标选择器。

完成标准：STS1 的主要卡牌机制可以由通用原语组合表达，不需要在引擎中识别具体卡牌、遗物或状态名称。

## P2：覆盖《杀戮尖塔 2》当前公开机制

### 卡牌级 Replay

- [x] 将 Replay 做成可附加到单张卡牌的参数化关键词。
- [x] 支持多个 Replay 来源叠加。
- [x] 明确 Replay 是否重新选择目标、是否产生完整出牌事件及如何避免递归。

说明：持续来源提供的 Replay 窗口与单卡补丁式 Replay 均已纳入统一结算。

### Enchantment 与 Affliction

- [x] 实现可持久化的正面卡牌补丁包。
- [x] 实现敌方施加、带移除条件的负面卡牌补丁包。
- [x] 支持数值、费用、关键词、自动打出、打出限制和永久成长组合。
- [x] 界面显示来源、实际规则和剩余持续时间。

### Sly

- [x] 只在合法弃牌原因和玩家回合阶段自动免费打出。
- [x] 回合清理、占卜和非弃牌移动不得误触发。
- [x] 自动打出失败时定义明确去向。

### Stars 与多资源费用

- [x] 将资源从单一能量改为资源映射。
- [x] 支持一张牌同时要求多种资源。
- [x] 支持跨回合保留资源。
- [x] 区分真正免费、只免普通能量和只免某一种资源。
- [x] 支持多资源 X 费。

### 召唤单位与 Osty

- [x] 独立生命、状态、攻击来源和死亡流程。
- [x] 拦截未格挡攻击。
- [x] 治疗、强化、攻击次数和来源修饰。
- [x] 多个召唤单位时的顺序和目标选择。
- [x] 普通自身与显式召唤者目标分离，可由无生命召唤表达持续、激活与离场容器。

### Doom 与直接处决

- [x] 通用 `execute/kill` 原语。
- [x] 按生命阈值检查，不经过普通伤害与格挡。
- [x] 正确触发或排除击杀、受伤和 Fatal 事件。

### Forge 与模板组修改

- [x] 确保对应卡牌首次存在或生成。
- [x] 跨所有牌区修改同模板/同族卡牌。
- [x] 明确是否影响未来副本和整局永久实例。

### 多玩家目标

当前长期目标暂不实现多玩家。以下内容保留为远期记录，不纳入本轮验收：

- [ ] （暂缓）自己、另一名玩家、指定队友、所有玩家目标。
- [ ] （暂缓）跨玩家触发器和共享计数器。
- [ ] （暂缓）向队友牌区加入卡牌或复制队友效果。
- [ ] （暂缓）多玩家结算顺序、断线恢复和存档一致性。

完成标准：只能表述为“覆盖当前公开 EA/Beta 机制”，不得声称覆盖尚未完成的正式版。

## P3：整局与战斗外系统

- [x] 统一奖励、商店、营火、删卡、复制、变形和升级事务。
- [x] 战斗外卡牌变化写回稳定整局实例。
- [x] 支持奖励替换、重投、禁止某类奖励和奖励池修改。
- [x] 遗物、能力、状态和战斗外规则共用触发器、来源、计数器与日志。
- [x] 失败时回滚整次购买、领取或牌组修改。
- [x] 长期存档升级与旧存档迁移。

## 每项机制的统一验收清单

新增机制只有满足以下全部条件才算完成：

- [x] 使用通用原语，不判断具体卡牌、状态、遗物或敌人名称。
- [x] 紧凑 AI DSL 和内部 AST 都有严格 Schema。
- [x] 非法字段、冲突字段、除零、递归和空目标有明确错误。
- [x] 第二轮 AI 世界书只写抽象契约，不写限制生成自由度的具体范例。
- [x] 战斗页面、奖励页面和普通状态栏复用同一效果说明生成器。
- [x] 战斗日志记录来源、目标、实际数值和触发原因。
- [x] 存档、读取、回滚和旧数据迁移通过测试。
- [x] 桌面端和移动端交互可用，不出现横向滚动或内容遮挡。
- [x] 单元测试、事务测试、长流程测试和生产构建全部通过。

## 推荐实施顺序

1. 卡牌身份与生命周期。
2. 统一选择器扩展。
3. 通用卡牌补丁与作用域。
4. 事件原因、阶段和历史计数器。
5. 完整牌区事务及生成/复制/变形/升级。
6. 动态费用、类型化伤害和规则替换。
7. 姿态、Orb、额外回合和多敌人。
8. Enchantment、Affliction、Sly 和多资源。
9. 召唤单位、Doom 和 Forge；多玩家继续暂缓。
10. 战斗外整局事务。
