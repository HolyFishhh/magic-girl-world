# 剧情模式长期验收（0.5.142）

## 范围

本轮继续验收剧情模式主线：首次初始化、普通剧情增量更新、第一场战斗、胜利奖励与领取、携带成长后的第二次遇敌、战败惩罚和战败后继续游玩。爬塔模式不在本轮范围内。

## 已完成的真实模型流程

`real-story-loop-0.5.141.log` 保存了真实 SillyTavern 与真实额外模型的完整分阶段证据：

1. 首轮建立玩家核心、初始卡组、遗物、道具和欲望效果。
2. 普通剧情轮保持现有卡组，不重新初始化永久内容。
3. 第一战胜利后由程序结算生命与经验，额外模型只生成三张卡牌候选和一个道具候选。
4. 领取后的卡牌与道具进入长期状态，并在第二次遇敌时保留。
5. 第二场失败后没有胜利奖励，生成剧情支持的永久负面状态，且玩家仍可继续输入剧情行动。

流程中发现第二次遇敌错误增加经验，现已把 `battle.level` 与 `battle.exp` 收敛为“仅首次初始化可写、之后只由程序结算”，并在真实长期流程脚本中加入越权断言。

## 战斗运行时修复

真实页面在玩家欲望接近满值时结束回合，复现了无限递归卡死：敌方行动触发欲望满溢，敌方欲望效果又增加玩家欲望，旧实现会在清零前再次触发同一效果。`UnifiedEffectExecutor` 现按玩家/敌人分别建立欲望满溢防重入锁；效果结束或抛错后统一在 `finally` 清零并释放锁。

确定性回归覆盖：

- 欲望效果自身继续修改欲望时只触发一次，不递归卡死。
- 连续点击同卡两次只出一张。
- 拖动到投放区只出一张。
- 拖动到区域外或 `pointercancel` 时实体卡回到原槽，手牌 ID 顺序不变。
- 全屏兼容模式保存并恢复 iframe 样式与酒馆宿主滚动状态。
- 双战长期流程允许剧情明确的胜利代价和多项战败惩罚，但阻止模型重复结算经验。

本轮针对新增风险另外执行生产方法级回归 `scripts/test-lust-overflow-reentrancy.mjs`：

- 玩家与敌人两侧的欲望效果都在效果内部再次请求同一侧满溢；实际执行次数均为 1。
- 正常完成和效果抛错两条路径都在 `finally` 中把对应欲望归零并释放锁。
- 该测试直接调用生产 `UnifiedEffectExecutor.handleLustOverflow`，不是复制算法的替身实现，并已纳入 `test:event-flow`。

真实结束回合点击未计为通过证据：测试期间本地 SillyTavern 进程自身停止响应，重启后当前 Codex 任务又不在可附着的前台窗口。服务使用同一数据目录恢复后，官方接口再次读回成功。未重复声称浏览器没有实际完成的点击；新增运行时路径由上述生产方法回归和完整发布门禁覆盖。

## 第二次遇敌复核

为节省模型请求，`0.5.142` 从已完成证据恢复到 `post_battle_growth`，复用既有剧情正文，只重新请求一次额外模型并在 `second_encounter` 后停止。结果：

- 卡组数量保持 13，遗物 1，道具 2，`secondEncounterPreservedContent=true`。
- 等级保持 1，经验保持程序结算后的 25；输出中没有 `battle.level` 或 `battle.exp` 命令。
- 新敌人“笑面皮囊”通过战斗预检，并以敌方欲望 `8/100`、玩家生命 `87/100` 承接先手剧情。
- 更新共 4 条命令，无旧值不匹配；证据保存于 `real-story-loop-0.5.142.log`。
