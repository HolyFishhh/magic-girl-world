# 剧情模式最终验收：0.5.130

## 验收边界

本报告只覆盖当前主线：剧情模式可以从首轮初始化开始，多轮推进剧情和成长，自动遇敌，完成胜利奖励，继续第二次遇敌，并在战败后留下合理惩罚后继续游玩。爬塔模式仍只是不可点击的预留入口，不计入本次验收。

主模型只生成剧情正文并长期读取持久变量；MVU 第二阶段读取完整变量快照并执行最小增量更新；战斗、经验、抽牌和胜负由程序确定。模式锚点、远征状态、当前敌人、临时战斗态和奖励事务不占用普通剧情模型的长期上下文。

## 真实模型长流程

长流程使用本地 SillyTavern 1.18.0、酒馆助手 4.9.3、玩家导入的剧情预设和 `deepseek-v4-flash`。模型调用发生在 `0.5.129` 开发候选上；随后到 `0.5.130` 的改动只有战斗 UI 收尾、重复提示删除、版本元数据和发布文档，没有改变已经通过的变量语义与结算流程，因此没有再次消耗相同的六阶段模型调用。

| 阶段 | 验收结果 |
| --- | --- |
| 首轮初始化 | 完整核心数值、玩家 Emoji、初始牌组、遗物、道具和玩家欲望效果一次性建立，就绪门禁通过 |
| 普通剧情轮 | 只进行增量变化，牌组、遗物、道具等持久内容未被重新初始化 |
| 第一次遇敌 | 第二阶段按剧情注册敌人，保留战前已经发生的生命、欲望与状态变化，战斗预检无错误或警告 |
| 胜利与领奖 | 程序结算经验；第二阶段生成 3 张卡牌与 1 个道具候选；领取后持久牌组和资源增长，奖励事务清空 |
| 第二次遇敌 | 已领取成长内容继续存在，新敌人依据新剧情注册，战斗预检无错误或警告 |
| 战败惩罚 | 不生成胜利奖励；只新增一种主题化永久负面状态，临时敌人和结算事务清空，剧情模式继续满足就绪条件 |

## 真实酒馆 UI 验收

最终 `魔法少女世界 0.5.130.png` 已通过 SillyTavern 官方接口导入为独立角色，并使用无模型战斗夹具验证最终发布代码，避免用静态网页代替酒馆验收。

- 酒馆读回：版本 `0.5.130`，世界书 `魔法少女世界0.5.130` 共 20 条，角色正则 7 条，角色脚本 `MVU变量框架`、`魔法少女世界运行时` 均存在且已授权。最终作者备注补丁复核时重复导入同一版本，因此本地文件名被酒馆自动追加为 `魔法少女世界 0.5.1301.png`；角色显示名仍是 `魔法少女世界 0.5.130`。
- 开始页：剧情模式默认可用，爬塔模式可见但禁用；表单可空着开始；11 个世界观方向和 12 个非强绑定卡牌方向存在。
- 常态状态栏：时间完整显示，字体为 10px，未出现省略或裁切；自定义行动输入框已经移除。
- 战斗页：实际 iframe 为 519×640，水平与垂直方向均无溢出；敌方、星空舞台、手牌、我方和底部按钮同屏可见。
- Buff 详情：显示名称、描述、层数、类型、完整触发时机和中文公式效果，内容区可滚动。
- 修饰符：按我方、属性、敌方三列对照显示，目标归属和实际计算一致。
- 牌区：完整牌组、抽牌堆、弃牌堆和消耗堆入口均存在；完整牌组逐张显示叙事描述和可执行效果。
- 卡牌交互：详情绑定当前卡牌与拖动幽灵；手牌使用 Pointer Events，单张拖动，不启用浏览器原生 `draggable`。

## MVU 性能与展示

- 第二阶段只携带一份完整当前变量快照，删除结构世界书中的重复动态快照。
- thinking 关闭，历史 2 层，最大回复 2600 token，失败后最多顺序重试 2 次。
- 角色世界书测量：普通更新约 2377、首轮约 8273、遇敌约 8279、战斗结算约 6651 token。
- 生成中自动打开独立加载窗；非流式请求显示旋转状态；完成后显示自然语言字段变化，不展示原始更新命令。
