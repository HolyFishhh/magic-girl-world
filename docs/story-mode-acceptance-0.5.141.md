# 剧情模式长期验收（0.5.141）

## 范围

本轮只验收剧情模式主线：玩家初始化后进入第一场战斗，胜利并领取奖励；构筑与资源继续保留，随后注册第二名敌人；第二场战败后不生成胜利奖励，并允许同时留下多项剧情支持的持久惩罚。爬塔模式不在本轮范围内。

用户明确要求浏览器人工操作由用户执行，因此本报告区分“确定性程序验收”和“尚未执行的酒馆视觉手测”，不以静态预览冒充酒馆交互结果。

## 确定性长期流程

`scripts/test-story-mode-long-flow.mjs` 使用与生产页面相同的初始化检查、战斗预检、程序结算和奖励事务，连续执行以下状态变化：

1. 初始化 11 张牌、1 个遗物、2 个战斗道具、玩家形象和欲望效果，并通过完整初始内容检查。
2. 第一名敌人通过战斗预检；胜利后玩家生命写回、道具数量同步、经验只由程序增加、敌人清理。
3. 第二阶段生成两张候选卡和一个候选道具，同时保留正文已明确形成的胜利代价；玩家领取一张卡和一个道具后，候选与选择限制全部清空，原初构筑数量没有被重新初始化。
4. 第二名敌人继承成长后的构筑，并以 `29/42` 的非满生命进入战斗，证明剧情中的战前伤害可以进入战斗快照。
5. 第二战失败后生命为零、经验不增加、敌人清理、胜利奖励为空；第二阶段同时登记诅咒牌、负面遗物和两项永久状态，且剧情模式不会被误切换为爬塔模式。

## 战斗交互证据

- `cardPlayInteraction.ts` 是点击与拖动结果的单一判定来源：第一次点击选中、第二次点击同一实体卡出牌；达到拖动阈值后仍走拖动；投放区内出牌，区域外或 `pointercancel` 恢复。
- 取消拖动不保存返回矩形。实体卡被插回不可见槽标记之前并恢复原内联样式；槽标记异常消失时只回退到原手牌父容器。
- 全屏优先请求原生 iframe/文档全屏。原生接口被拒绝时，兼容路径保存 iframe 原样式与酒馆宿主滚动状态，使用 fixed viewport 覆盖；退出或按 Escape 后逐项恢复原值。
- 交互策略、原槽恢复、全屏覆盖与恢复均有可执行测试；生产边界测试另外确认按钮、事件监听、样式和战斗壳层的实际接线。
- 最终角色运行时另外直接检查 `card-drag-slot`、`pointercancel`、`mwg:play-card`、`requestFullscreen`、`100vw`、最高层级和全屏激活类，防止只修改源码或测试夹具却漏进单卡生产包。
