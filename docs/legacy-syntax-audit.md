# 旧效果语法审计

审计对象是 `worldbook_new/2战斗内容生成要求.md`
规定的自制效果字符串，以及解析、预检、执行和 UI 显示链。目标不是让程序更容易解析，而是减少 AI 首轮完整卡组输出中的记忆负担、括号负担和不可局部修复错误。

## 结论

> 2026-08-23 完成：`0.5.76` 保留为最后一个旧字符串实机回退点；`0.5.77` 生产协议只支持现代浅层 JSON + 简易公式。旧 `ME/OP`、`target.trigger(effects)`、旧条件/选择器/插牌字符串及对应 parser、host、adapter、反向展示转换和专用测试均已删除。

旧语法能表达当前游戏的大部分能力，但把 8 套规则压进一个字符串：目标视角、数值公式、效果分隔、条件、触发器、状态、卡牌选择器和 JSON 插牌。复杂卡并不是线性增加难度，而是让这些规则互相嵌套。一次漏括号、漏引号或错误逗号会使整场战斗在初始化前失败，模型也很难根据字段路径只修一个局部。

新格式保留 JSON 卡牌对象，单个效果可直接写浅对象；常见同条件效果也可组合在一个浅对象中。程序内部再编译为 `mwg.effect/v1`；AI 不输出内部 AST。

## 高风险语法面

| 旧入口   | 例子                                 | AI 负担或歧义                                        | 新入口                                     |
| -------- | ------------------------------------ | ---------------------------------------------------- | ------------------------------------------ |
| 相对目标 | `ME/OP/ALL`                          | 视角随玩家、敌人、能力归属和状态持有者翻转           | `self/opponent`；常用效果有默认目标        |
| 效果链   | `A, B, C`                            | 逗号也可能出现在触发器、条件分支和插牌 JSON 内       | 单对象/组合对象；有先后依赖时用 `effects` 数组 |
| 条件     | `if[c][a]else[b]`                    | 三组中括号必须成对，分支又能嵌套效果链               | 同级 `when`；单值二选一用三元公式          |
| 触发器   | `ME.turn_start(...)`                 | 外层 `ME` 表示能力归属，内层 `ME` 又按归属者解释     | 卡牌同级 `trigger`；少数例外效果写 `on`    |
| 状态     | `OP.status apply bleed 2`            | ID、层数和目标只靠空格位置                           | `apply_status/stacks/to` 同级字段          |
| 选择器   | `reduce_cost.discard.all+draw.all 1` | 点号、空格、`+`、数字后缀承担不同语义                | `from/pick/count` 同级字段；跨牌区拆成多项 |
| 动态插牌 | `add_to_hand {"effect":"..."}`       | 卡牌 JSON 内再嵌效果字符串，生成牌再生成牌时多层转义 | `add_card` 引用同级 `creates` 模板         |
| 弃牌效果 | `discard_effect: "..."`              | 第二套旧字符串入口                                   | `discard_effects` 浅数组                   |
| 新旧别名 | `damage:8`、`trigger:value`          | 多种表面相似写法并存                                 | 新世界书只生成一个规范格式                 |

## 输出长度实测

测量命令：`npm run measure:card-output`。样本使用最小化 JSON，分词器为 `gpt-tokenizer 4.0.0` 的
`o200k_base`；数值不包含聊天消息框架、世界书提示和模型隐藏开销。

| 样本                         | 数组包装 token | 直接/组合对象 token |   差异 |
| ---------------------------- | -------------: | ------------------: | -----: |
| 单一伤害牌（无重复描述）     |             30 |                  28 |  -6.7% |
| 伤害 + 格挡                  |             34 |                  32 |  -5.9% |
| 生成两张临时攻击牌           |             75 |                  66 | -12.0% |

历史测量中字符串单一伤害牌为 `39 token`，两类触发器 Power 为 `87`；当前浅层 Power 为 `89`。新格式不再输出重复 `description`，因此实际首轮完整卡组通常更短；测量脚本现只保留当前协议样本。

新格式的目标不是在每张复杂牌上绝对省 token。单效果组合对象比数组更短，顺序复杂牌仍可能增加字段 token；换来的收益是：无需成对生成多层括号、无需转义内嵌 JSON、错误能定位到
`effects[index].field`，并可由编译器拒绝未知变量、模板循环和非法选择器。

为控制开销，当前契约采用以下压缩原则：

1. `damage/heal/block/energy/lust` 自带常用默认目标，只有反常目标才写 `to`。
2. 数字直接写数字，不包装成 `{amount: ...}`。
3. 同一 Power 的常用触发器只在卡牌级写一次；只有例外效果写 `on`。
4. 复杂条件拆成并列 `when`，不输出内部条件树。
5. 动态卡牌模板只定义一次，效果用短 ID 引用。
6. 单个效果省略数组包装；同条件的常见数值/状态/抽牌效果合并为一个对象。需要顺序依赖时才使用数组。默认值不输出：`stacks=1`、`from=hand`、常用 `pick`、`count=1`、布尔字段为 false 时全部省略。

## 不采用的方案

- 不让 AI 输出 `spec/op/target/amount/steps` 完整 AST：嵌套和 token 都过高。
- 不以 YAML 或另一套自制行语法替代 JSON：缩短少量标点，但重新引入缩进、分隔和字符串转义歧义。
- 不允许任意 JavaScript、`eval` 或函数调用：真实酒馆中的消息内容不应成为代码执行入口。
- 不再以旧聊天为由保留双协议；先用 `0.5.76` 留下可回退角色卡，再按“世界书 -> 生产调用点 -> 兼容模块 -> 测试”顺序删除，并对最终新语法卡做一次真实酒馆回归。
