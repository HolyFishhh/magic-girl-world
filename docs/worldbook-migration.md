# 世界书迁移记录

> 当前协议以 `0.5.92` 为准：主模型只输出剧情，不输出选项或变量；MVU 额外模型独占 `[mvu_update]` 条目。下方旧版本记录只用于解释迁移过程，不代表仍支持 `<Options>`、混合模型职责或旧语法。

### 0.5.92 两阶段模型职责收口（2026-08-24）

- 所有正式条目改为单一 `[mvu_plot]` 或 `[mvu_update]` 标签，不再存在 mixed 条目。剧情模型看到可读状态和构筑效果；变量模型看到 schema、浅层 JSON、公式与更新命令。

`battle.statuses`；动态插入卡牌的完整字段、主效果和弃牌效果也递归预检。动态插牌失败必须抛回所属事务，禁止吞掉错误后留下半执行状态。23. 敌人行动声明必须确定：只接受四种正式模式，sequence/probability 中的行动名称必须存在、权重必须为正有限数；同域内容 ID/行动名称必须唯一，玩家与敌人的生命/欲望必须处于
`0..max`。任何问题在选择器运行前阻止初始化，禁止静默随机兜底或去重丢项。24.
MUV 外层战斗结构先于内容预检和消息快照恢复校验：规范 `stat_data.battle` 一旦存在便拥有绝对优先级，错误时不得回退旧平铺
`battle`；`core`、`enemy`、必需有限数值、非空敌人名和 `cards` 数组会以 `battle.<field>` 精确路径报错。`MISSING_BATTLE`
仍表示当前消息没有战斗，不视为坏数据。25. 消息快照只在完整符合当前运行时不变量时恢复：敌我核心数值必须是有限数且处于范围内，必需牌堆/状态/行动必须是数组，回合、阶段、终态字段必须合法。存在但损坏的快照标记为陈旧并从当前 MUV 重建；不得把坏快照恢复后再依赖 UI 或效果执行器兜底。26. 卡牌支付语义必须明确：`energy`
只读取扣费后的实时能量，`spent_energy` 只读且表示本次实际支付。新 X 费牌使用 `cost: "energy"` 与
`spent_energy`；后者不允许目标前缀，只能用于 Attack/Skill/Event 主效果。旧 X 费牌中对 `energy/current_energy`
的引用仅由兼容层按历史支付值解释。27. 卡牌生命周期由统一规则决定：Power 打出后无条件进入消耗堆，防止能力重复注册；打出的普通牌在自身效果完整结算后才进入弃牌/消耗堆，因此不能被自己的抽牌效果立即洗回。`narrate`
只允许 Event 的主效果使用，且每张 Event 必须恰好包含一个顶层 `narrate`。28. 卡牌操作必须有精确运行时语义：`draw`
只表示立即抽取，且只允许 `+`/`=`，结果为 0 时不得偷偷回退成 1；`exile.selector` 和旧 `exhaust.selector`
都必须使用合法选择器，并把目标从当前牌区真实移动到消耗堆。29. `trigger_effect.selector`
的双重标记必须进入消息快照，并在下一次成功出牌时让主 effect 在同一事务中执行两遍；费用和 `card_played`
只结算一次，任一遍失败则整体回滚且标记保留。Event/Curse 不可标记。`cards_played_this_turn`
在主效果前递增、失败随事务回滚，并在新玩家回合开始时清零。
