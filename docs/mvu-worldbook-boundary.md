# MVU 世界书职责边界

`0.5.93` 使用严格的两阶段模型链路。世界书 comment 中的标签是访问边界，不是普通标题。

| 标签 | 接收者 | 职责 |
| --- | --- | --- |
| `[mvu_plot]` | 主模型 | 角色扮演、剧情推进、敌人外观与行为描写、构筑方向提示 |
| `[mvu_update]` | MVU 额外模型 | 读取已完成剧情，输出唯一的 `<UpdateVariable>` 变量补丁 |
| `[config_override]` | MVU 配置读取器 | 卡级配置，不进入任何模型提示词 |
| `[initvar]` | MVU 初始化器 | 初始 schema 模板，禁用为普通世界书条目 |

项目没有混用条目。`scripts/test-worldbook-contract.mjs` 会拒绝同时带有 `[mvu_plot]` 与 `[mvu_update]` 的正式条目。

## 主模型

主模型能看到时间、地点、职业、生命、等级、卡牌效果、遗物、道具、NPC、势力与世界设定，因此可以围绕玩家现有火焰、防御、状态等机制推动剧情和帮助凑构筑。它不接触：

- `_.set/_.assign/_.remove/_.add` 更新命令；
- 卡牌公式和完整变量 schema；
- 敌人数值、行动权重和战斗 JSON；
- 奖励候选 JSON；
- AI 选项协议。

普通回复只写自然剧情。确定进入战斗时，先完整描写敌人及遭遇，再在末尾单独输出 `<BATTLE_PENDING>`。主模型永远不输出 `<BATTLE_START>` 或 `<UpdateVariable>`。

## MVU 额外模型

额外模型只接收 `[mvu_update]` 条目，以主模型已经写出的剧情为事实来源。它负责：

- 初始化和更新 `stat_data`；
- 根据剧情中的敌人描述注册敌人、行动、能力和本场状态；
- 生成初始牌组、遗物、道具和奖励候选；
- 输出浅层 JSON + 简易公式的 MVU 函数命令。

输出必须是一个 `<UpdateVariable>`。除 `<Analysis>` 外，每个非空行都是完整的 `_.set/_.assign/_.remove/_.add` 命令。禁止 XML 树形 `<Set>/<Add>/<Item>`、Markdown 代码块、剧情续写和选项。

## 战斗交接

```text
主模型：剧情和敌人描述 + <BATTLE_PENDING>
  -> MVU 额外模型：注册 battle.enemy 等变量
  -> BEFORE_MESSAGE_UPDATE：校验 enemy.name 与 actions
  -> 校验成功：把标记改为 <BATTLE_START>
  -> 校验失败：保留 <BATTLE_PENDING>，不打开错误战斗页
```

这个顺序保证第一次生成只负责叙事，第二次生成才把叙事转换为可执行数据。

## 默认配置

角色卡的 `[config_override]` 固定：

```json
{
  "更新方式": "额外模型解析",
  "额外模型解析配置": {
    "启用自动请求": true,
    "世界书条目白名单正则": "^\\[mvu_update\\]"
  }
}
```

兼容假流式和默认复用当前主连接由卡内加载器在首次安装时写入全局 MVU 设置；它们不是角色级 `[config_override]` 字段。角色卡不保存 URL、API Key 或模型名。用户以后可在 MVU 面板切换独立模型；这不会改变世界书职责。

## Token 预算

运行 `npm run measure:worldbook-roles` 可重新测量。`0.5.93` 的 `o200k_base` 静态上限为：

- 主模型全部 `[mvu_plot]` 条目：约 2828 token；
- 额外模型常驻条目：约 2860 token；
- 首轮完整内容生成：约 7702 token；
- 敌人战斗注册：约 7558 token。

选择性条目只在对应控制标记出现时加入，不会每轮把完整卡牌生成协议重复发送。
# 0.5.93 普通剧情链路修复

- 开始页在发送 `[角色创建]` 前必须等待当前楼层的 MUV/酒馆助手就绪。首轮回复是初始变量更新的唯一入口，不能让 `MESSAGE_RECEIVED` 在 MVU 聊天级监听器安装前触发。
- `首条消息变量更新` 显式使用 `scan_depth=2`，因为 `[开始游戏]` 位于创建用户楼层，而额外模型处理的是随后生成的助手楼层。
- 普通剧情用户输入不携带战斗开关。输入只描述玩家行动，主模型根据剧情决定是否输出 `<BATTLE_PENDING>`；程序不再提供“按当前行动进入战斗”的强制按钮。
