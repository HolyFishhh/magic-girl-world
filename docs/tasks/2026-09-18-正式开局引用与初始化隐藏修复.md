## 根因与范围

- 诊断包含四次开局记录：三次是馈赠 `card_ref` 被当作完整卡牌校验，一次是读取 `crypto.subtle.digest` 崩溃。默认单次开局 Prompt 已明确要求卡牌引用，但默认请求 Schema 和接收路径没有展开引用；既有引用集成测试只覆盖 registry 草稿入口。
- 新版 `renderStoryPanel`/`renderCharacterStatus`/`renderTowerScreen` 重新显示独立剧情与状态栏。旧的初始化逻辑只隐藏旧 `.statusbar-*` 面板；另外剧情区 `display:flex` 会覆盖浏览器对 `hidden` 的默认样式。
- HTTP 非安全上下文可能没有 SubtleCrypto，初始化凭据计算直接调用它会在模型结果已经返回后崩溃。附件没有域名或安全上下文证据，因此不能断言玩家当时的部署协议；修复覆盖该缺失接口条件。
- 默认路径还漏存 `provider-final`。附件只有校验错误，无法完整离线重放当次卡组。新增记录保留原回复，失败也可以导出。

## 实现

- `initialCardReference.ts` 提供两条开局协议共用的严格引用解析。只复制本次 `player.cards` 中唯一完整定义，保留效果、召唤物、本地模板及依赖，奖励数量独立；拒绝悬空/链式引用、覆盖字段和非法数量，不按名称猜卡。
- 默认请求 Schema 显式启用引用分支；规范存档、普通节点和有限修复 Schema 仍只接受完整定义。接收边界在正式校验和有限修复之前展开引用，因此既有执行、中文两条说明链、候选预览和领奖事务继续使用同一完整结构。
- 保存摘要增加标准 SHA-256 兼容实现，缺失 SubtleCrypto 时输出与原生相同的 64 位十六进制摘要；不放宽提交/恢复校验。供应商能力缓存复用相同实现。
- 爬塔初始化无已提交 run 时，三个渲染入口保持剧情区和状态栏隐藏；显式 `[hidden]` 样式防止 flex 覆盖。生成失败/重试继续隐藏，开始页仍可用；成功、第二幕、终局和归档恢复正常。普通剧情模式展示不据牌组为空自动隐藏，避免误伤合法空牌组。
- 修复打包回归中的旧 `0.3.5` 常量：核对当前 manifest，并实际核对扩展控制器的能力版本；角色运行时测试也使用当前扩展版本。
