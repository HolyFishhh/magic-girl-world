## 本轮问题与修复

- 剧情模式已有牌组删牌入口，却仍自动打开塔模式共用的删牌弹层。现在剧情模式仅用牌组右上角“删牌”，卡牌下方显示“移除这张”；未用次数保留。爬塔继续使用选择器，取消不消耗次数。共享中文说明不再宣称所有模式均立即弹窗。
- 删牌接入统一的精确实例事务和修订号校验，避免同名升级副本误删、双击重复消费与旧页面误写。刷新后保留删牌模式，次数用尽、空牌组或历史楼层禁用。按钮移到卡面下方，窄屏触控高度至少 44px。
- 只读核对当前聊天：1286 字符为遭遇敌人时的变量更新块；848 字符为程序发送的战斗胜利摘要用户消息。原监控把后到的摘要解析回调计入已完成请求，误报缺少 UpdateVariable。成功后忽略迟到的 complete/stream/reasoning；真正的新请求和后续内容校验失败仍正常报错。
- 结构化胜利奖励原先按 JSON 字符串比较 limits，字段顺序也可能触发整轮重生成。领取名额本就由程序预算决定，现在直接恢复 request.limits，保留有效候选，不因排序、多余零值或错误名额重问模型。其他不可执行内容仍校验，失败最多一次结构修正。
- 自动结算先校验已有完整奖励；奖励齐全且可执行时，仅同步预算并清理未完成标记，保留卡牌、物品、现有成长与剧情后果，不调用模型。缺失或不可执行的奖励仍走受限修复。仍使用聊天/楼层/回复作用域及成对正文变量提交，冲突时保留新数据。
- 选牌弹层和卡牌完整预览按酒馆实际可见视口定位，防止长 iframe 中内容被压缩或落在屏外。列表独立滚动，底部操作可见；手机完整预览保留完整风味文字。卡面选择和详情阅读分别处理，详情不改变选择。诊断提示明确使用深色文字，避免继承酒馆主题的浅色字。
