# 剧情模式原布局恢复

用户反馈爬塔模式更新后，剧情模式原有内容全部不可见，后续恢复又把酒馆已经显示的剧情正文重复包进了状态界面。调查确认世界书、剧情开场、NPC、势力、衣物与背包数据并未删除；问题来自公共页面被新的爬塔统一状态栏接管，以及剧情模式误用了爬塔的正文面板。

## 本轮修复

- common + story 只恢复原状态栏、人物关系、势力关系、卡牌资源和自由行动布局；剧情正文继续由酒馆消息直接显示，不创建 `#mwg-story-panel`，战斗时只切换到战斗页面。
- 修复通用界面正则曾把整条助手消息替换成 iframe 的根因：剧情模式现在只替换消息末尾的 `UpdateVariable`、内容交接和状态占位符，正文仍由酒馆原生 Markdown 渲染，状态栏接在正文后方。
- 爬塔控制器改用内部 `<TOWER_STATUS/>` 标记，通用正则仅对该标记执行整条消息接管，因此爬塔继续使用自己的正文、节点与历史面板，不会因为剧情模式恢复原生正文而出现双份内容。
- 战斗壳同步恢复剧情模式原生正文：只替换末尾的变量更新、`BATTLE_START` 和状态占位符，战斗前剧情留在酒馆消息中，随后挂载当前最新战斗页面。爬塔战斗继续在 `<TOWER_STATUS/>` 单层界面内切换，不经过剧情战斗正则。
- 只有 tower 才创建正文面板和统一状态栏，并搬移地图、节点和奖励。剧情模式不会读取 `run_node`、`completed_expedition`、`mwg_tower_initial_commit` 或战后剧情缓存，也不消费路线事务或唤醒待生成的幕间开场。
- 原卡牌资源面板继续使用当前结构化卡牌与规则说明，并补充能力、当前战斗状态及层数、资源、我方欲望效果、当前姿态和召唤成长。
- `battle.player_lust_effect` 继续接受有效的结构化效果，但空名称、空描述和 `$meta` 组成的 MVU 可选模板视为未提供，不再强制生成欲望效果，也不会触发修复。
- 当前模型输出中出现的 `eff果s:null` 仅在同张卡已经存在合法 `effects` 时作为无语义污染移除；非空 `eff果s` 仍保留给严格校验报错，未知字段规则没有整体放宽。
- 现有剧情字段和存档只读保留，不重建、不迁移、不推进玩家存档。设计辅助器的剧情 MVU 上下文、有限修复和持久写回路由经检查无需修改。
