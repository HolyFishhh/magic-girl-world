# 流派与评分修复、机制缺口评估（2026-09-22）

承接 [上一轮审查](2026-09-22-archetype-scoring-audit.md)。本轮修复确定的分析错误，并评估执行器能力边界；没有增加未经配套的新 DSL 或卡牌机制，没有变更小怪 20%、精英/Boss 50% 的软克制概率，没有按质量拒绝或改写合法内容。

## 已修复

| 问题 | 修改与验证结果 |
| --- | --- |
| 持有状态身份造成缓存串用 | 新增独立的 `evaluation2` 指纹，保留身份及完整输入；静态分、影子画像、影子试打、流派和设计上下文使用正确的评估依赖。换皮/近似结构匹配继续使用原来较粗的指纹。切换 +1 / +20 状态后，缓存与清空缓存的结果一致，强状态正确更高 |
| 欲望无击杀也拿满分 | 正式试打记录 `enemyHpRemaining`，未获胜时按敌方实际剩余生命计算清敌进度。伤害过量、敌人回疗与欲望反复累积不再刷进度；真实胜利仍为 100%。测量/结果协议升级为 v2，缺少末态证据明确为未知，不猜测旧记录 |
| 合法护盾欲望对照 | 2 套牌各 8 场景 × 3 策略 × 2 种子，共 96 次正式执行，全部到达测试回合上限、0 次胜利、伤害为 0；仅防护与防护+非致命欲望均为 **35%**，后者原为 100% |
| 灵巧与零费漏识别 | 灵巧识别为弃牌收益/自动执行，并连接主动弃牌来源；原生零费能识别为零费连锁，不要求人为添加 free。遗弃/遗忘记录为不同风险，显示本场移除/永久删牌，不虚构弃牌收益或静态收益数值 |
| 恢复/倍率/转化误判 | 治疗目标与状态持有者参与分析；治疗敌人不建立己方恢复流。减伤+攻击不再建立倍率爆发或恢复转化；欲望、恢复转化需要数值依赖或相应事件，保留 compact/compiled 两种形式一致性 |
| 基础牌阈值断崖 | 纯数值攻击/格挡在流派证据中按相同规则处理，6→7 不再改变主流派。零费、多段、穿透、吸血、唯一等实际区别仍保留；全部合法数值仍参加战斗与强度计算。已同步基础机制识别与生成引导，更新旧阈值断言并保留正反例 |
| 无关状态白拿分 | 静态特征从玩家拥有且可达的定义收集，添加无法获得的状态不再改变分数。满溢定义只有存在欲望来源时才计入流派，不因“库中有定义”凭空形成构筑 |
| 资源稳定性 | 初始/固定刷新资源决定初始可用性。无法获得法力与初始有法力的对照，稳定性从原来同为 65，变为 **30 / 65**。后续产能与连招仍由试打补充，静态说明明确其范围 |
| 敌人行动周期 | 固定序列按完整周期计算。攻击 30 后等待四次，平均主动伤害正确为 **6**，不再是 15；短局爆发仍提示结合公开意图 |
| 敌人被动与遗漏输入 | 被动实际收益/条件和阶段频率未完整模拟时降低覆盖并说明原因；反伤 1/100 仍不能用静态小计比较，但不再显示 100% 覆盖。姿态、球体、持续改造/召唤成长纳入画像缓存依赖，影子模型未支持的初始内容明确列为不完整估计 |
| 界面解释 | 流派占比明确为机制证据权重，不是强度、胜率或成型概率；实测说明欲望须通过实际满溢收益发挥作用 |

这不是评分系统全面重做：成熟度面板、同种子奖励边际实测、更多克制对局、精细的被动静态频率推断仍属后续阶段。没有把低覆盖结果冒充准确强度。

## 机制核对：已有能力

以下以当前代码和回归为准，不仅凭关键词名判断：

| 能力 | 当前入口 / 证据 |
| --- | --- |
| 灵巧、遗弃、遗忘、先天、虚无、保留及牌区生命周期 | `cardLifecycle.ts`、`test-card-traits.mjs`、`test-card-lifecycle.mjs`；灵巧不响应回合末自动弃牌，遗弃/遗忘响应所有弃牌 |
| 15 种预设通用状态与剧情自定义状态 | `builtinStatusCatalog.ts`；力量、敏捷、虚弱、易伤、脆弱、中毒、再生、金属化、仪式、荆棘、壁垒、活力、人工制品、无实体、缓冲。仅展开实际引用定义，不替换自定义“黑暗仪式”等身份 |
| 抵消负面、伤害上限、阻止生命损失、反伤 | `statusDefense.ts` 与两组 status-defense 回归；**人工制品、无实体、缓冲已实现，不能重复列为缺失** |
| 敌方保护与召唤护卫 | `damageProtection.ts`、`test-damage-protection.mjs`；攻击拦截、分摊与召唤拦截已有特定语义，不等于任意结算都可改写 |
| 敌人条件行为与玩家事件响应 | `battleTriggers.ts`、敌人行动宿主、事件查询与公式；出牌类型、实际花费、受击、血量/状态条件等已有能力；不能因静态估分不支持就说执行器没有实现 |
| 多资源、X 费用、动态费用、跨战斗保留资源 | `combatResource.ts`、`dynamicCardCost.ts`；支持组合费用、全额投入、费用修改和 `end_of_battle:retain` |
| 生成、复制、重放、牌序、改造、永久成长 | `effectDsl.ts`、`cardPatch.ts`、`persistentGrowth.ts` 及契约矩阵；同时有附魔/负面附着、未来副本/实例身份等范围 |
| 召唤、阵型、指令、死亡后再次召唤、姿态、球体 | 正式 DSL 和执行器已有对应操作。影子估分覆盖不足是分析层缺口，不能等同于这些机制没有实现 |

《尖塔 2》官方介绍的 Afflictions 是敌人向卡牌施加负面改动的方向；项目已有 affliction/card patch 通路，当前优先确保作用域、到期、保存和显示正确，而非再造一套同义机制。[Mega Crit 官方说明](https://www.megacrit.com/news/2025-4-15-neowsletter-issue-9/)

## 建议补充的执行能力

这些是本项目的设计建议，本轮没有实施。判断“缺少”指缺少通用正式协议，某些固定案例可能已经能用现有操作组合表达。

| 优先级 | 缺口及当前边界 | 可增加的玩法 | 实施时必须明确 |
| --- | --- | --- | --- |
| 高 | **状态选择与转移**：目前以具体状态 ID 施加/移除；未发现按类别/标签选择未知状态并原子转移、复制的通用操作 | 偷取敌人一个增益、把一个负面转给敌人、任选一个负面净化、扩散某个状态 | 持有者、来源、层数/期限、可转移范围、选择取消；不能通过同名状态猜 ID |
| 高 | **可替代和额外费用**：现有复合费用是资源分量共同支付；没有“能量或生命二选一”“牺牲指定召唤物作为支付”等统一成本事务 | 鲜血施法、献祭出牌、弃一张牌换取免能量、资源替代 | 支付可行性须在出牌前检查，取消/失败应完整回滚，实际花费事件不能记成印刷费用；自伤效果不自动等于生命费用 |
| 中 | **通用结算前拦截/替换窗口**：现有触发器主要观察既成事件，另有专门防御通道；没有统一的 before-damage/before-play 待结算事件协议 | 条件格挡反击、抵消一次技能、把本次伤害替换为资源损失 | 拦截优先级、一次性消耗、来源身份、递归阻断和取消语义。只扩确有需要的窗口，避免为整个游戏加入复杂响应栈 |
| 中 | **卡牌永久移除限制**：当前生命周期有永久删除，但未发现不可移除/绑定卡的统一字段与校验入口 | 剧情核心卡、必须通过事件解除的诅咒 | 商店、奖励、剧情删牌、遗忘、自身效果、转化统一检查，并区分“不能删”和“不能变形”；不能只禁用一个 UI 按钮 |

其中“状态选择/转移”与“额外费用”最直接扩充目前状态流、吸血/自伤流和召唤流；“通用拦截”涉及结算顺序，建议在前两项完成后单独设计。新增机制必须同时完成 Prompt/世界书、Schema、编译、有限修复白名单、执行/取消、存档及两条中文说明链，不能只允许 AI 写出字段。

不建议为了补机制数量立即引入多人联机、完整战棋地图或通用响应栈。现有资源、卡牌改造、召唤和状态已经能组合出很多玩法，优先让分析与实际执行一致。

## 验证及限制

- 新增 `test-archetype-score-accuracy.mjs`，调用合法内容诊断并断言缓存、目标、因果、词条、资源和周期结果；验证编译前后、序列化往返和不改写输入。已纳入稳定性集。
- 正式引擎合成对照 96 次完成；结果保存在本机 `tmp/scoring-after-measured.json`，没有使用玩家存档。
- 稳定性集 28 组通过，另有 15 组定向验证通过（与稳定性集有重叠），覆盖流派、基础机制引导、奖励、设计上下文、影子模型和正式试打；应用与扩展两个 TypeScript 检查通过。旧回归中三处数值 7 阈值预期随本轮产品语义更新，仍保留编译对称、特殊牌正例和基础牌反例。过程中发现无来源的满溢定义会误添主轴，已修为仅在存在欲望来源时加入，原回归通过。
- 本轮未调用真实模型、未推进聊天、未领取奖励、未刷新用户页面。仅新增评分说明文字，无新交互布局；不宣称玩家实玩验收或新的浏览器视觉验收。
