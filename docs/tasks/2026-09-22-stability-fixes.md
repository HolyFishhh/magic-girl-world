# 稳定性验证与修复：第一批

依据 [整体审查](2026-09-22-overall-audit.md) 与 [分阶段计划](../design/2026-09-22-stability-experience-plan.md)。本批由主代理直接执行，未使用子代理。优先交付已复现的数据一致性和战斗错误，并处理诊断脱敏、依赖与字体阻塞。

## 已修复的行为

- 前台事务、后台生成、剧情写回、恢复和成对修复共用同源顶层窗口的 MVU 提交锁。独立 bundle 共享该锁；AI 请求和用户选择不占用提交锁。按读取基线三方合并，允许不同字段同时更新，同字段冲突拒绝，不重放扣费、随机或奖励 updater。回读失败明确标注结果未确认。后台可复用草稿同时推进内容与基线，避免第二次提交撤销刚合入的数据。
- 运行时固定消息身份；等待期间换聊天、楼层、回复或冒险时取消旧提交。锁仅协调本项目入口，不宣称能为第三方直接写 MVU 提供宿主原生 CAS 或磁盘事务。
- 删除整局历史读取的 20,000 条硬上限。22,000 条合法事件能往返 JSON，并继续归档；相同遭遇重复归档不增加记录。已有但损坏/不支持的历史明确报错并保留原值，不再当成空历史覆盖。提示词压缩预算与存档合法性分离，超预算仍使用完整 JSON。
- 界面刷新不再释放动作锁；动作令牌防止旧 finally 解锁新操作。营火、商店离开/删牌、新冒险等入口补齐锁；旧页面异步结果不再更新新页面的反馈。预选只在成功进入后通知。
- 召唤物/护卫完全拦截攻击时，原目标不再重复反伤；原目标确实承受攻击且完全格挡时仍可反伤。攻击者身份及反伤不递归规则保持。
- 同链双方致死时先处理双方死亡反应，再按既有核心规则判定胜利；仍有敌人生存时判负。双方各生成一次最终死亡事件。
- 玩家伤害和敌人意图预览与执行共用状态伤害上限计算，覆盖攻击、效果伤害和生命流失；预览不消耗缓冲等真实状态。该数值仍是伤害包预览，不冒充护卫、随机目标和所有后续触发后的精确失血预测。
- 统一诊断文本脱敏，覆盖带引号/转义键的 JSON、Basic/Bearer、access/refresh token、密码等；递归对象脱敏不修改原对象。运行时诊断/后备输出和后台错误摘要使用共享函数。玩法数据、留证原文的既有保存契约未改写。
- 远程字体移出阻塞 CSS import，在视图初始化时以非阻塞样式表加载，跨视图去重；系统字体先显示。

本批不新增玩法协议字段；已有世界书、Schema、有限修复字段表和两条中文说明链继续使用同一防御/弃牌契约，不需要修改世界书或迁移玩家数据。

`npm audit --omit=dev --ignore-scripts --json` 当前返回生产依赖告警 0 项。证据：`tmp/stability-dependency-audit-final.json`。这不代表完整系统没有漏洞：UI 的 Lodash/YAML externals 仍由宿主提供，本次不升级酒馆宿主全局库。

## 验证

- 应用和扩展独立 TypeScript 检查。
- `npm run test:stability`：统一维护存档并发、切换取消、失败恢复、长历史、战斗、预选、界面和生命周期回归；加入日常 `test:mechanism-completion` 入口。
- `npm run test:sts2-mechanics`：预设、防御、弃牌、通用卡牌规则、敌方能力、软克制抽签及预选。也接入机制完成入口。
- 隔离 Chromium 直接运行生产字体加载器，扣留 Google 字体请求期间初始化和点击均可完成，随后模拟离线也不破坏界面状态。证据：`tmp/optional-font-browser-vu4hMT/evidence.json`。该夹具不是完整酒馆实玩。
- 补全 `test-card-traits` 的 DOM 模拟接口；旧源码匹配测试同步动作令牌参数，预选测试直接加载真实锁函数，未删除机制断言。

源码验证已通过：23 组稳定性回归、11 项尖塔机制脚本、双类型检查、独立字体浏览器测试；最终补充的嵌套死亡归属同时通过防御端到端、事件因果/复活、伤害保护和终局回归。日志为 `tmp/stability-regressions-delivery.log`、`tmp/stability-sts2-regressions.log`。候选 `stability-20260922-r3` 正在隔离构建，安装完成后追加回读证据。测试目标：显示名 **魔法少女世界 1.0.3**；精确头像 **魔法少女世界 1.0.3.png**。不刷新已有页面，不推进聊天或玩家存档，不调用真实模型，不推送或正式发布。
