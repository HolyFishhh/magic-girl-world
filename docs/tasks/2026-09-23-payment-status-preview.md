## 现象与核对

- 用户截图中的「血色献祭」显示「替代费用『以血献祭』…（替换全部通常费用）」及「赋予3层未注册状态」。对应结构化状态引用是 `sts_strength`（已登记的内置「力量」），而该会话的 `battle.statuses` 没有同 ID 定义。此处的“未注册状态”是展示上下文缺失，不代表 `sts_strength` 不受支持；旧快照缺定义的具体写入环节尚不能由截图确定。

## 修改与边界

- `describeCardPayment` 统一显示 `可选替代：方案名，完整费用`，删除「（替换全部通常费用）」；费用替换、生命至少保留 1 点、放弃／支付行为不变。卡牌详情与效果标签使用同一文案。
- 两条中文说明对精确内置状态 ID 使用目录名称回退，已登记的同 ID 剧情定义仍优先；仅内置白名单适用，其他缺失定义继续提示未注册。非战斗选择、爬塔开局馈赠、事件、篝火回忆及初始遗物预览以正在预览的内容补齐所需内置定义和规则引用，不把未领取候选写进存档。
- 不修改 Prompt、Schema、编译协议或既有玩家聊天／存档。旧快照缺定义的原始生成原因尚未确定；这次保证预览可读，并保留运行时已有恢复闭包。新运行时须由玩家自行完整刷新页面才能生效。
