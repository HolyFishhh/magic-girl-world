# 流派体系与设计方法

本条是卡组、奖励与敌人机制创作的结构索引，不是固定牌表、职业模板或题材预设。流派名称只帮助理解；真正判定只看 `effects`、`trigger`、状态、资源、牌区、召唤与其他可执行字段。卡名、emoji、描述、角色职业和叙事表现均不参与机制成立判定。

## 使用方法

1. 先读取用户明确写出的机制或流派要求，再读取当前剧情身份、已有卡组、`battle.design_context` 的流派占比与缺口。用户明确指定的机制必须真实实现；用户未指定时只把本图谱当作创意空间，不强迫套入某个流派。
2. 一个稳定流派至少包含“启动端”和“收益端”，较窄的流派还应有维持、转换、风险或终结环节。只写一个普遍有用的数值效果时，把它视为通用散卡，不要伪造流派归属。
3. 初始牌组的核心启动端必须有足够数量或检索能力，使玩家能在正常抽牌中实际进入循环；收益端必须能把积累转化为伤害、欲望、防护、资源、控制或其他可执行优势。不能用一张难以抽到的孤立卡声称整副牌已经实现该流派。
4. 一张卡可以同时服务多个相邻流派；奖励可深化现有循环、补齐收益、连接相邻节点、渐进转向或作为通用散卡。不要把每张牌都强制归类，也不要跨越多个不相邻机制突然重写构筑。
5. 先决定结构，再按当前世界观创造名称与表现。禁止反过来根据名字猜效果；描述中声称发生的核心机制必须存在于可执行字段中。
6. 所有操作仍服从“战斗内容生成要求”。本条只决定机制如何组合，不放宽字段、目标、状态注册、公式和生命周期契约。

## 当前卡牌流派图谱

### 即时压力与终结

- 直接压制：启动与收益都是稳定的即时 `damage`；抽牌、能量或资源只负责提高持续出手能力。
- 多段连击：启动是一次行动产生多次实际命中；运转依赖命中次数或命中事件；收益由逐次触发、状态、资源或修饰形成。
- 倍率爆发：启动是可累积的状态、资源、条件或修饰；运转是保留并放大倍率；收益是在明确窗口集中造成伤害。
- 斩杀终结：启动是生命阈值或击杀条件；运转是把目标推进终结区间；收益必须由 `execute` 或 `kill` 真正完成终结。

### 状态与双胜利轴

- 状态积累：启动是注册并反复 `apply_status`；运转是维持或增加层数；收益读取层数产生压力、修饰或条件优势。
- 持续伤害：启动是带伤害结算的状态或 `schedule`；运转跨回合维持与叠加；收益在合法触发时持续造成实际伤害。
- 状态引爆：启动是先积累状态；运转是等待合适层数；收益通过 `remove_status` 消费状态并集中转化为伤害、欲望、防护或恢复。
- 状态转化：启动是建立可读取状态；运转读取层数或状态事件；收益把它转换为另一压力轴、格挡、恢复或资源。
- 状态成长：启动是获得或施加状态；运转由持有、叠加或相关事件持续强化；收益落在后续伤害、防护、抽牌或能量上。
- 敌方状态反哺：启动是让敌方持有、获得或失去状态；运转监听相应条件或事件；收益回到己方防护、恢复、牌序或资源。
- 欲望压制：启动与收益都是真实 `lust` 压力；运转通过持续施加、条件或触发推进欲望胜利轴。
- 欲望溢出：启动是把敌方推进欲望满溢；运转围绕满溢窗口准备；收益必须由玩家欲望效果落实为足以逆转或终结的可执行结果。
- 欲望转化：启动是欲望变化或欲望状态；运转读取、保存或转换该变化；收益落在生命伤害、格挡、恢复或自定义资源。
- 双轴压制：启动同时建立生命与欲望两种真实压力；运转根据局势切换或并行推进；收益允许任一轴完成战斗，但两轴不能只存在于描述中。

### 防护、生命与风险交换

- 格挡循环：启动是稳定获得 `block`；运转由抽牌、能量、触发或修饰保持防守节奏；收益是用更低资源成本持续抵消压力。
- 格挡留存：启动是获得格挡；运转通过持续规则或回合触发跨回合保存；收益为延迟成长和后续兑现争取时间。
- 格挡转化：启动是获得、持有或消耗格挡；运转读取格挡量或格挡事件；收益转换为伤害、欲望或资源。
- 反击：启动是承伤、失去生命、获得格挡或成功防御的事件；运转保持可触发窗口；收益向敌方返还真实压力。
- 恢复循环：启动是可靠 `heal`；运转通过触发、资源或牌序重复恢复；收益是延长资源交换和成长时间。
- 恢复转化：启动是治疗或生命变化；运转读取治疗事件、治疗量或生命差；收益转化为伤害、欲望或资源。
- 自伤交换：启动是明确作用于己方的生命伤害或生命支付；运转需要风险控制与回收手段；收益必须提供超出普通效率的压力、资源或其他优势。
- 残血爆发：启动是已损生命或低生命条件；运转主动管理危险区间；收益在条件成立时强化伤害、防护或恢复。

### 手牌、牌序与牌区循环

- 抽牌引擎：启动是稳定 `draw`；运转解决费用与手牌容量；收益是提高关键组件到手率并连续触发其他机制。
- 快速轮转：启动由 `draw`、`scry`、`seek` 或 `recover` 增加牌库访问；运转缩短循环；收益是更频繁使用关键牌。
- 弃牌引擎：启动是主动 `discard`；运转改善手牌并重复制造弃牌事件；收益由弃牌触发、抽牌、能量、资源或压力产生。
- 弃牌收益：启动是可控弃牌；运转累计本回合或本场弃牌事件；收益按事件或数量兑现，不能只把弃牌当作无补偿代价。
- 消耗引擎：启动是主动 `exhaust`；运转精简循环并触发消耗事件；收益来自伤害、防护、抽牌、能量或回收。
- 消耗回收：启动是让牌进入消耗区；运转用 `recover` 从 `exhaust` 取回；收益是把一次性牌转为受控循环资源。
- 弃牌堆回收：启动是把关键牌送入弃牌堆；运转从 `discard` 定向 `recover`；收益是形成稳定短循环。
- 牌顶控制：启动是 `scry`、`seek` 或移动抽牌堆卡牌；运转安排顶部、底部与顺序；收益在未来抽牌、自动出牌或条件结算时兑现。
- 牌库精简：启动是 `remove_card`、`exhaust` 或 `transform_card` 清理低效牌；运转提高核心牌密度；收益是更稳定、更短的循环。

### 费用、保留、回响与触发

- 零费连锁：启动是 `free` 或 `reduce_cost`；运转用抽牌和低费牌扩展单回合行动数；收益由连续出牌、压力或状态触发兑现。
- 费用操纵：启动是 `reduce_cost`、`patch_card`、`modify_card` 或免费规则；运转跨牌与跨回合安排费用；收益是在资源窗口打出原本受限的行动。
- X费爆发：启动是积累可支付能量或资源；运转保留并选择投入量；收益由 `x_cost` 或 `x_formula` 把投入转换为可调效果。
- 保留蓄势：启动是 `retain` 或明确的牌区去向规则；运转跨回合保存关键牌并等待条件；收益在资源、状态或时机成熟时集中结算。
- 回响连锁：启动是 `replay` 或 `double`；运转让完整卡牌重复结算；收益同时放大卡牌本体和出牌触发，不得只把重复写进描述。
- 自动出牌：启动是合法来源与时机上的 `auto_play`；运转管理失败去向、牌区和触发；收益是获得额外行动而不破坏牌区一致性。
- 出牌触发：启动是卡牌被实际打出的事件；运转按次数、类型或顺序累计；收益由 `trigger` 或历史公式产生伤害、防护、抽牌、能量或状态。
- 命中触发：启动是实际造成伤害的命中事件；运转通过多段、回响或频繁攻击增加事件；收益追加状态、资源、防护或牌序优势。
- 持续能力：启动是打出能力或获得带 `trigger` 的被动；运转跨后续回合持续改变规则与收益；收益必须存在于触发效果或合法持续修饰中。
- 延迟收益：启动是 `schedule` 预约未来结算；运转管理延迟时间与生存窗口；收益在约定回合产生压力、防护、恢复、抽牌或资源。

### 资源、衍生牌与卡牌成长

- 资源引擎：启动是先注册并生成自定义资源；运转稳定获得、保留与消费；收益把资源转换为伤害、防护、抽牌或恢复。
- 资源蓄积：启动是可跨回合保留的资源；运转持续积累并避免无效溢出；收益在高价值窗口集中消费。
- 资源兑现：启动是建立足够资源；运转选择消费时机；收益通过公式、条件或设值把资源集中转为伤害、欲望、防护或状态。
- 多资源编织：启动是至少两种已注册资源；运转让资源相互供给、转换或共同支付；收益来自多条资源链汇合，而不是仅把资源并列命名。
- 衍生牌：启动是 `add_card`、`ensure_card` 或 `copy` 产生可执行卡牌；运转管理生成位置、数量与去向；收益由衍生牌的真实效果与相关触发产生。
- 卡牌成长：启动是 `upgrade_card`、`patch_card`、`attach_card` 或 `transform_card`；运转在合法生命周期内保留变化；收益体现在卡牌实际数值、费用、关键词或规则上。
- 附魔构筑：启动是 `attach_card` 的正面附着；运转管理唯一附魔、范围与移除条件；收益真实改变所附卡牌的数值、费用、关键词或结算规则。
- 负面附着：启动是可追踪的负面 `attach_card`；运转围绕承受、移除、转化或利用进行交换；收益与风险都必须由可执行附着规则体现。
- 诅咒利用：启动是牌区中存在真实 `Curse`；运转通过弃牌、消耗、变形或触发管理诅咒；收益把负面牌转化为可执行优势。
- 牌库污染：启动是向对方牌区 `add_card` 或 `ensure_card` 加入真实干扰牌或诅咒；运转降低抽牌与出牌质量；收益表现为可执行的弃牌、消耗、回合或规则压力。

### 容器、召唤与战场控制

- 姿态切换：启动是进入真实 `stance`；运转在互斥形态间切换；收益通过各姿态的资源、修饰、触发或规则差异改变决策。
- Orb循环：启动是 `channel_orb` 或建立槽位；运转管理槽位、被动结算、强化与 `evoke_orb`；收益由 Orb 的真实被动或主动效果产生。
- 召唤协同：启动必须包含真实 `spawn_summon`；运转至少使用召唤行动、触发、援护、资源、强化、治疗、复制或选择器互动；收益由召唤实例或 `summoner_effects` 实际产生。只有召唤名称和描述而没有召唤实例时，本流派未成立。
- 召唤群攻：启动是产生多个可行动召唤实例；运转通过额外行动、召唤触发、强化或资源维持群体；收益由多个实例持续施压或相互协同。
- 召唤献祭：启动是先建立可消费召唤；运转选择 `damage_summon` 或 `dismiss_summon` 的对象与时机；收益集中转化为压力、抽牌、资源或新的召唤循环。
- 多目标压制：启动是 `targets` 对全体、随机、数量、生命排序或指定实体选敌；运转根据存活目标重选或锁定；收益处理多敌局势而不是把单体效果写成群体描述。
- 意图反制：启动是可观察的行动、条件或事件；运转保留正确响应窗口；收益用防护、反击、状态或规则改变回应敌方意图。
- 规则控制：启动是 `card_rule`、回合控制、牌区去向或额外回合规则；运转在明确范围和触发时机内改变行动约束；收益来自节奏与选择权变化。
- 拖延控制：启动是减益、防护、规则限制或延迟；运转延长己方成长窗口；收益必须有可结束战斗的伤害、处决或资源兑现，不能形成无终点循环。
- 额外回合：启动是 `extra_turn` 或受控 `end_turn`；运转重排双方行动节奏并限制循环；收益由额外行动中的压力、防护、抽牌或资源产生。
- 随机博弈：启动是随机目标、随机数量或随机牌的真实选择；运转管理结果范围与失败风险；收益用更高上限补偿不确定性，不能把普通确定效果只写成随机叙事。

## 通用散卡

通用散卡不需要形成独立循环，可以负责基础伤害、防护、恢复、抽牌、资源修正、状态清理、目标修正或操作容错。它们可以补短板、提高稳定性或成为两个相邻流派之间的桥，但不应因为带有一个常见操作就被强行归入多个流派。程序会保留散卡占比，也会降低难以打出、低效率或偏离当前构筑且没有独立价值的卡牌评分。

## 敌人机制设计方法

敌人不需要照抄玩家卡组，也不要求每个敌人完整对应一个流派节点。先从本轮剧情中的身份、形态、环境与行为能力提取可执行动作，再按以下顺序组织遭遇：

1. 选择一个主要压力轴，使敌人能够真实推进战斗结束；再选择零到两个能与主轴发生因果关系的副机制。副机制数量不是复杂度指标，没有协同就应省略。
2. 把行动组织成“铺垫、施压、兑现、保护或调整”这些功能角色，并根据敌人的行动模式安排节奏。角色可以合并或缺省，不要求固定行动数量和固定循环。
3. 为高收益行动提供玩家可观察的信号、条件、蓄势、可打断对象、可清除状态、资源窗口或其他反制入口。反制方式由剧情和现有机制决定，不预设固定答案。
4. 每个核心行为都必须落到合法 `effects`、`trigger`、状态、资源、召唤、增援、牌区干扰或规则字段。名称与描述只负责表现；若删掉描述后不存在对应机制，就说明设计仍是换皮。
5. 敌人若以召唤为核心，必须真实使用 `spawn_summon` 或需要正式加入胜负判定时使用 `spawn_enemy`，并通过行动、能力、召唤选择器或战场关系产生互动；不能把普通伤害卡改成召唤措辞。
6. 敌人可以借用图谱中的启动、成长、转换、兑现、风险与控制关系，也可以组合相邻节点；不要按流派目录逐项拼装，不要为了覆盖更多标签堆叠无关机制。
7. 谱系记忆只维持确有关系的敌人连续性。继承的是至少一个可辨认的行动结构、状态关系或机制轴，再按当前位阶演化；不是复制完整敌人，也不是只复用名称。
8. 强度预算决定数值上限，不决定题材和机制。生命、欲望、控制、格挡、成长、召唤与牌库压力共享预算；加入更强控制或成长后，应相应减少其他压力。

以上流程是创作方法而非硬性牌表。剧情事实、用户要求、当前卡组和程序预算决定最终设计；图谱负责提醒机制怎样真正成立，以及怎样避免只有叙事标签而没有玩法。
