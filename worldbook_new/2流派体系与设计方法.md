# 流派体系与设计方法

基础牌边界：只有普通攻击或格挡且数值严格小于7的卡牌不作为已有流派证据，但仍是战斗能力的一部分；低数值且具有条件、连击、成长、触发、特殊目标或额外资源支付的卡牌按实际机制识别。

开局复选菜单、机制识别与后续生成共用程序的基础流派目录；不得另造一份限制玩家选项的职业名单。后续请求中的 `foundationGuidance` 分别提供玩家选择偏好、持有内容的结构证据与完整机制家族；偏好不等于已拥有配合。奖励、商店、事件和新幕馈赠要参考这些信息，补足启动/维持/收益缺口，或用实际共享的资源、模板身份与触发事件连接新方向，不只重复当前最高分流派。目录可自由组合，名称与题材不能代替机制；不要求每张卡包含所有选择，不强制固定候选比例，也不改写合法旧卡。识别由本地程序完成，不额外请求一次 AI。

本条是组合索引，不是职业模板或必选牌表。卡名、emoji、描述和职业不参与机制成立判定，只看真实 effects、trigger、状态、资源与容器。语法、目标和生命周期统一服从“战斗内容生成要求”。

## 使用方法

先读玩家要求与已成立剧情，再看已有卡组和 battle.design_context。按“要求 → 具体机制链 → 效果核对”创作；未指定部分自由发挥，不强制归类。以下核对在同一次生成内完成，不新增输出字段或检查报告：

<!-- shared:mechanism-review -->
1. 需求→结构：先把每项明确要求落实为完整机制链，再补散卡。复合要求不能只做一半；名称、说明、注册定义或相近机制不算实现。
2. 定义→入口：每个引用有定义，每条所需机制有实际启动入口。状态须有施加来源，生成牌须有生成来源；普通卡须能取得并打出，已持有监听器须满足其真实启用时机。未领取奖励不算开局已有。依赖敌方或后续剧情的条件可以保留，但不能冒充开局自足循环。
3. 入口→结算：核对发生者、持有者、目标、条件、支付、收益及结束；玩家与召唤分开，计数对应事件与范围。读取资源不等于消耗，获得不等于叠加，本回合末不等于后续回合。按执行顺序逐步检查，不把后一步条件套到无条件步骤。
4. 结构↔说明：每项承诺都有对应效果，每个效果的条件、目标和时机都表述一致；包括欲望效果与临时牌。欲望效果只属于真实欲望体系；一旦采用，满溢的数回合积累兑现须明显超过普通单卡，以同等回合与费用用于直接输出能取得的累计收益为参照，并计入触发后的持续收益；不能只多一点，主副轴均不得低收益。发现遗漏先补完整机制，不删需求、不改说明掩盖缺失；未指定部分自由创作，不固定载体或数值。

下列各项按“启动 → 运转 → 收益”阅读，是创作方法而非硬性牌表。一张牌可连接相邻机制，奖励可深化、补缺、桥接或渐进转向；不为覆盖标签堆叠无关规则，不突然重写玩家构筑。名称与表现最后依世界观创作，不能反过来按名字猜效果。

## 当前卡牌流派图谱

### 召唤卡的构思建议（非强制）

大部分召唤卡优先设计为打出后消耗，控制本场重复召唤；消耗不等于永久删牌。专门围绕复数召唤、补充召唤物或循环展开的卡牌可不消耗，依剧情与构筑自由设计，不作为校验条件。

### 即时压力与终结

- 直接压制：damage → 牌序与费用支持 → 连续压力。
- 多段连击：多次命中 → 逐次命中事件 → 状态、资源或修饰收益。
- 倍率爆发：积累 → 保留与放大 → 窗口爆发。
- 斩杀终结：阈值条件 → 压低目标生命 → execute/kill。

### 状态与双胜利轴

- 状态积累：apply_status → 维持层数 → 层数收益。
- 持续伤害：状态/schedule → 跨回合维持 → 到期伤害。
- 状态引爆：积累 → 选择窗口 → remove_status 消费整个状态并兑现，不是部分扣层。
- 状态净化：不利状态或需消耗的状态 → remove_status 移除指定状态或层数 → 清理风险或兑现既有收益；只讲净化，不承担复制或转移。
- 状态复制：来源持有符合筛选的状态 → status_action 选择并复制给目标 → 目标获得同一状态身份与期限；选择取消即取消本次操作，不能借此移除来源状态或改变未选状态。
- 状态转移：来源持有符合筛选的状态 → status_action 选择并转移给目标 → 目标接收的层数才从来源移除，保留状态身份与期限；选择取消即取消本次操作，未接收的层数仍留在来源。
- 伤害前拦截：状态已在场并声明 before_damage → 仅在该次伤害结算前拦截 → 取消、替换或改写该次伤害；不是任意时点的通用触发，也不补做伤害后的结果。
- 出牌前拦截：状态已在场并声明 before_card_play → 仅在该次卡牌效果结算前拦截 → 取消卡牌效果或替换为有限 effects；已付费用不退、出牌事件仍成立，不是撤销选牌或任意时点触发。
- 状态转化：建立状态 → 读取层数或事件 → 另一压力轴或资源收益。
- 状态成长：获得状态 → 持有、叠加或事件强化 → 后续行动增益。
- 敌方状态反哺：敌方状态 → 条件或事件监听 → 己方收益。
- 欲望压制：lust → 持续联动 → 满溢窗口，不自动胜利。
- 欲望溢出：敌人满溢 → 玩家 `player_lust_effect`（self=玩家，opponent=满条敌人）；玩家满溢 → 来源敌人的 `lust_effect`（self=来源敌人，opponent=玩家）。绝不自己满溢触发自己的效果。
- 欲望转化：欲望变化 → 读取或转换 → 伤害、防护、恢复或资源。
- 双轴压制：生命与欲望压力 → 切换或并行 → 两轴有效且有可执行终局。

### 欲望主副轴的收益规范

- 只有存在真实欲望施压、积累、读取或转化入口时才生成欲望效果；仅有 lust 数值栏或情色题材不算欲望体系。
- 满溢通常要积累数回合：无论主轴或副轴，兑现须明显超过普通单卡，以同等回合与费用用于直接输出能取得的累计收益为参照，并计入触发后的持续收益；不能只比普通卡多一点，更不能用少量资源、防护、再次加欲望或普通行动充数。
- 先推演“填满 → 兑现 → 后续路径”：对照对手生命、恢复与本方生存窗口，确认直接收益、完整注册的持续收益、召唤/成长或其他已实现联动能回收实际投入；还要再次积累才兑现的链条，须计入额外投入。间接收益必须连到可执行伤害、胜负结算或等价战局优势。
- 这是相对收益衡量，不指定固定伤害、固定回合数或硬编码终结；强力不等于无预兆秒杀，敌人仍须保留可读的反制窗口。不得因为剧情主题强制纯欲望流。

### 防护、生命与风险交换

- 格挡循环：block → 牌序、费用或触发维持 → 抵消压力。
- 格挡留存：格挡 → 合法跨回合保存 → 延后兑现。
- 格挡转化：格挡 → 数量或事件读取 → 伤害、欲望或资源。
- 反击：承伤或防御事件 → 保持响应窗口 → 返还压力。
- 恢复循环：heal → 资源、牌序或触发维持 → 延长交换时间。
- 恢复转化：治疗/生命变化 → 事件或数值读取 → 行动或资源收益。
- 自伤交换：自伤/生命支付 → 控制风险 → 交换收益。
- 残血爆发：低血条件 → 管理危险窗口 → 条件增益。

### 手牌、牌序与牌区循环

- 抽牌引擎：draw → 费用与容量支持 → 提高组件到手率。
- 快速轮转：draw/scry/seek/recover → 缩短访问循环 → 复用关键牌。
- 弃牌引擎：discard → 真实弃牌事件 → 牌序、资源或压力收益。
- 弃牌收益：可控弃牌 → 正确范围内累计 → 事件或数量收益。
- 消耗引擎：exhaust → 精简循环与消耗事件 → 行动收益或回收。
- 消耗回收：进入消耗区 → 从 exhaust recover → 受控复用。
- 弃牌堆回收：进入弃牌堆 → 从 discard recover → 短循环。
- 牌顶控制：scry/seek/移动 → 排序 → 抽牌、自动出牌或条件收益。
- 牌库精简：remove_card/exhaust/transform_card → 提高核心密度 → 稳定循环；战斗移除不等于永久删牌。

### 费用、保留、回响与触发

- 零费连锁：free/reduce_cost → 抽牌与低费牌 → 连续出牌收益。
- 费用操纵：reduce_cost/patch_card/免费规则 → 合法寿命与窗口 → 费用收益；modify_card 本身不改费用。
- 额外支付：卡牌预先声明额外费用 → 出牌前同时校验并支付原费用与额外费用 → 获得该卡的正常出牌资格或效果；这不是效果树中的独立 op，不能在卡牌开始结算后补付或把不可支付的额外费用当作免费。
- 替代支付：卡牌预先声明替代支付路径 → 出牌前选择一条可支付路径并完整校验、扣除 → 获得该卡的出牌资格；替代方案完整替换通常费用和 additional，不改变卡牌效果、也不能把不可支付路径当作免费。
- X费爆发：积累可支付量 → 公开X费用 → 支付量公式兑现，不能发明 x_cost/x_formula 字段。
- 保留蓄势：retain/牌区去向规则 → 跨回合保存 → 窗口兑现。
- 回响连锁：replay_current/重放规则 → 完整重复结算 → 本体及出牌触发收益，不是重复伤害。
- 自动出牌：auto_play → 管理来源、失败去向与触发 → 额外行动。
- 出牌触发：出牌事件 → 类型、次数或顺序统计 → trigger/历史查询收益。
- 命中触发：命中事件 → 多段、重放或频繁攻击 → 追加收益。
- 持续能力：能力/被动 → 跨回合生效 → 触发或持续修饰。
- 延迟收益：schedule → 到期阶段与存续窗口 → 定时兑现。

### 资源、衍生牌与卡牌成长

- 资源引擎：注册并生成资源 → 保留与消费 → 行动收益。
- 资源蓄积：可保留资源 → 跨回合积累 → 高价值窗口消费。
- 资源兑现：准备资源 → 支付/公式/设值 → 实际收益；负数资源效果不自动构成必付费用。
- 多资源编织：至少两种资源 → 相互供给、转换或共同支付 → 联合收益。
- 衍生牌：add_card/ensure_card/copy → 管理位置、数量与去向 → 真实牌效果。
- 卡牌成长：upgrade_card/patch_card/attach_card/transform_card → 合法寿命 → 数值、费用、关键词或规则改变。
- 附魔构筑：正面 attach_card → 管理唯一附魔与移除 → 强化所附卡牌。
- 负面附着：负面 attach_card → 承受、清理或转化 → 可执行风险与收益。
- 诅咒利用：Curse → 弃牌、消耗、变形或触发 → 转为优势。
- 牌库污染：向对方 add_card/ensure_card → 干扰抽牌与出牌 → 牌区或规则压力。

### 容器、召唤与战场控制

- 形态联动：赋予自身指定形态状态 → 检查同一状态是否存在 → 解锁强化攻击、防御或资源收益；不要求反复叠层。
- 姿态切换：stance → 互斥形态切换 → 修饰或切换收益；passive不承载trigger。
- 姿态槽循环：channel_orb与槽位 → 被动结算、强化及evoke_orb → 被动与主动收益。
- 召唤协同：真实 spawn_summon → 行动、援护、强化、资源或选择器互动 → 实例或 summoner_effects 产生收益。
- 召唤群攻：多个行动实例 → 维持与强化 → 持续施压或协同。
- 召唤献祭：建立召唤 → damage_summon/dismiss_summon → 献祭收益。
- 多目标压制：targets → 按存活重选或锁定 → 实际覆盖多敌。
- 意图反制：可观察意图 → 响应窗口 → 防护、反击或控制。
- 规则控制：card_rule/回合/牌区规则 → 范围与时机 → 节奏收益。
- 拖延控制：防护、减益或延迟 → 争取成长窗口 → 可执行终局，不是无终点循环。
- 额外回合：extra_turn/end_turn → 合法重排并限制循环 → 额外行动收益。
- 随机博弈：真实随机目标、数量或选牌 → 管理范围与失败风险 → 风险对应收益。

## 通用散卡

散卡不要求独立循环，可补输出、防护、恢复、牌序、资源、清理或容错，也可连接相邻机制。单个常见操作不自动代表多个流派。程序的散卡占比、效率和亲和评分仅供参考，不授权删掉玩家要求的内容。

## 敌人机制设计方法

1. 从剧情身份、形态、环境和行为中提取一个主要压力轴，按需要加入真正协同的副机制；不要求照抄玩家卡组或覆盖图谱。
2. 行动承担铺垫、施压、兑现、防护或调整，可合并或缺省，不固定数量与循环。高收益行动应有可观察信号、条件、可清除状态、可打断对象或资源窗口。
3. 核心行为必须落到合法结构；召唤用 spawn_summon，参与独立胜负判定的增援用 spawn_enemy，不能靠改名实现。结构预算约束执行规模，强度预算平衡伤害、欲望、控制、成长、防护和召唤，不决定题材。
4. 只有剧情确有谱系关系才继承已有招牌行动或状态关系，再按位阶演化；不复制整套敌人，也不只复用名字。遭遇整体须有可执行终局路径，不要求每个动作或每次满溢单独结束战斗。


### 补充组合观察点

- 单核心养成：建立指定同槽核心 → 治疗、保护或强化该实例 → 核心持续行动兑现价值。
- 召唤被动成长：建立带触发能力的召唤 → 按真实回合或事件累积属性 → 增强后续输出、防护或主人收益。
- 召唤生命转伤：建立生命计伤的召唤 → 提高或恢复该召唤的生命 → 以实际 self.hp 或 self.max_hp 结算伤害。
- 召唤指令连动：建立与指令模板匹配的召唤 → 选中存活实例并令其行动 → 以该召唤为来源结算行动收益。
