# 剧情可见状态与构筑

当前 MVU 状态是剧情连续性的事实来源。本条目在每一轮剧情生成中常驻，下面展示的都是当前真实值；你只需要理解它们的意义，不负责修改，也不需要解释内部公式。不要因为某项本轮没有在正文出现就遗忘它，更不要把“没有提到”当成变量为空。

`battle.enemy`、`battle.player_abilities`、`battle.player_status_effects` 与 `reward` 不在普通剧情轮常驻注入，一次性战斗或奖励对象由对应事务消息按需提供。游戏流程专用状态同样不进入普通剧情上下文，剧情模型不读取、不判断也不修改。不要因为常驻区没有展示这些对象就推断其被清空。

把这些数据当成剧情事实。卡牌、遗物和道具中的 `name/description` 与浅层 `effects` 只用于理解它们在剧情中的实际作用；不要复述字段、计算公式、ID 或 JSON，也不要据此输出任何变量命令。

## 剧情中应关注

- `status`：当前时间、地点、职业、服装、剧情物品和长期/临时状态。正文与这些事实保持连续。
- `battle.core`：玩家当前生命、生命上限、欲望与上限。受伤、疲惫、恢复和欲望变化应在剧情中有合理表现。
- `battle.cards`：玩家实际拥有的卡牌。通过卡名、类型和效果理解玩家能做什么、构筑偏向什么；不要向玩家展示内部公式。
- `battle.artifacts/items`：遗物与战斗道具。让它们在剧情和选择机会中有存在感，避免遗忘已经获得的资源。
- `battle.statuses/player_lust_effect`：理解当前构筑的自定义机制与欲望满溢能力；它们没有程序内置含义，只能按变量中实际注册的中文名称、描述和效果理解。
- `battle.level/exp`：玩家成长阶段。只决定表现尺度，不要直接宣布程序尚未结算的升级。
- `battle.design_context.brief`：程序对当前构筑与最近实战的紧凑判断，只用于帮助剧情提供更相关的机会与挑战；它不是世界事实、不是硬配比，也不授权剧情模型修改变量。
- `factions/npcs`：势力关系、入侵强度和持续登场人物。保持立场、关系和行动连续。
- `reward`：只在奖励事务消息明确提供时理解为尚待玩家确认的候选；普通轮不常驻读取，也不要替玩家选择。

## 构筑友好叙事

判断卡组当前的主要胜利手段、防御方式、资源循环与已经形成的联动。剧情应优先提供以下帮助：

1. 补足明显的生存、恢复或资源循环缺口。
2. 强化已有主题，让玩家能逐渐形成明确而非随机拼凑的构筑。
3. 用敌人和环境检验构筑，但保留可观察、可应对的窗口。
4. 允许机制相近但叙事身份不同的内容存在，不因“效果类似”否定合理换皮。

你可以描述适合出现的奖励方向，但不要决定具体 JSON、数值、ID 或公式；这些由 MVU 额外模型根据同一段剧情生成。剧情模型每轮读取这些 MVU 值，但永远不输出变量命令；“持续读取”和“禁止写入”必须同时成立。


## 卡牌永久移除与变形限制

卡牌和 creates 模板的 lifecycle 可写 removable:false（不可永久移除）、transformable:false（不可变形），两项独立且默认允许。unique 不等于绑定。不可移除使商店、营火、事件和删卡次数均不能删除该实例；遗忘/打出销毁仍移出本场，但原卡战后保留。消耗、遗弃、战斗 remove_card 与复制不受永久移除限制。不可变形同时约束战斗 transform_card 和战外变形，仍可升级或修改数值；要让剧情核心牌既不能删又不能被替换，应同时设置两项 false。不能只在名称或描述中声称绑定。


## 状态选择、复制与转移

状态选择/复制/转移使用 {status_action:{mode:"remove"|"copy"|"transfer",from:"self"|"opponent",to?:"self"|"opponent",pick?:"choose"|"first"|"random",count?:1..999或"all",stacks?:1..999,filter?:{type?:"buff"|"debuff"|"neutral",ids?:[状态ID],tags?:[标签ID],min_stacks?:正整数}}。from 指当前精确持有者或当前对方，不接受群体 targets；召唤自己的 self 仍是该召唤。复制/转移必填 to；remove 不写 to；不能向自己转移。count 默认1，候选不足处理实际数量；pick 默认 choose（玩家手选且可取消，敌方自动随机），first 按持有顺序；stacks 省略处理选中状态全部现有层数。filter 字段同时满足，ids/tags 内任一匹配；状态定义根 tags 是可选且不重复的英文标签数组，类型中性写 neutral。复制保留来源，转移仅扣除目标实际接收的层数；目标层数上限、人工制品或不接收状态导致未接收时不丢失来源。层数和期限不重新计算；与同ID状态合并时取较长剩余期限，无期限优先；仍按该状态自身衰减规则运行，不能改名为力量等预设。目标写入、来源扣除在同一动作事务内完成，再执行来源移除与目标获得/叠加生命周期；取消或动作失败回滚。


## 额外费用与替代付款

卡牌和卡牌模板根部 payment 支持 additional:{hp:正整数,discard:{count:正整数,card_type?:Attack/Skill/Power/Curse/Status,tag?:标签},sacrifice:{count:正整数,template_id?:召唤模板ID}}，以及 alternatives:[{id:唯一ID(不能normal),name:剧情名称,cost:标准费用,...额外费用字段}]。additional 加在通常动态 cost 上；每个 alternatives 完整替换通常资源和额外费用，不继承 additional。玩家从可支付方案中选择，再选精确弃牌/献祭实例；取消整次出牌无消耗。HP直接扣除且至少保留1点，不是伤害；弃牌不能选正打出的牌，触发正常弃牌含灵巧/遗弃/遗忘；献祭执行离场/被击败触发，不留尸体。全部费用先同时扣除再触发收益，不得用费用触发收益支付本次费用。免费只豁免资源费用，自动打出选择首个可支付方案及符合条件的首批实例；重放仅首次付费。实际能量/资源统计不混入生命或实例数量。


## 结算前拦截

状态根部 intercepts:[{id,window:"before_damage"或"before_card_play",subject?:"self"(默认)或"opponent",priority?:整数,when?:通用条件,card_type?:Attack/Skill/Power/Curse/Status,damage_kind?:attack/effect/damage_over_time/hp_loss/retaliation,cancel?:true,amount?:数值或算术公式,replace?:浅层effects,consume_stacks?:正整数,uses_per_turn?:正整数,uses_per_battle?:正整数}]。cancel/amount/replace 恰选一项。出牌窗口只支持 cancel/replace 和 card_type；伤害窗口只支持 damage_kind 和三种结果。高优先级先，同优先级按持有者/状态/规则ID排序，取消/替换停止该次窗口。pending_amount 是当前包伤害；出牌窗口可读 event_paid_energy/total/resource及event_paid_hp/discard/sacrifices，重放这些支付量为0。self/opponent/stacks 以状态持有者为基准；subject:opponent作用于另一阵营。敌人的被动反制可用开场赋予此状态；召唤物持有时 self 仅精确召唤实例。伤害窗口在保护/召唤拦截及减伤之后、无实体/格挡/缓冲之前，包含生命流失但不包含支付生命费用；替换程序先执行，原伤害归零。出牌窗口在付费和费用触发之后、每次卡牌效果之前；取消不退费、不取消出牌事件/离手，不等于取消玩家选牌。只有玩家打出的卡（含自动/重放）有出牌窗口，敌方意图不是卡牌。次数按精确持有状态实例记录，移除后重新赋予重新计数，复制/转移不复制使用记录；无需强制次数上限，按设计平衡决定。活跃规则禁止自递归，整个窗口嵌套至多32层。
