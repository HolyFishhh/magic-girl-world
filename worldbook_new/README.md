# 世界书职责索引

本目录按“谁读取、何时读取、负责什么”组织。`manifest.json` 与 `entry-config.json` 的顺序就是导入后的阅读顺序；不要按文件名前缀推断职责。

## 1. 模式入口

- `爬塔开局剧情`：只在开始页提交 `[爬塔模式]` 时约束第一轮短开场，并明确由后续程序接管馈赠、地图和节点；不会污染剧情模式。
- `首条消息变量更新`：卡组为空时的一次性初始化，是初始化字段与输出顺序的唯一详细定义。
- 游戏模式、模式锁与爬塔运行状态由程序写入。AI 只能读取任务明确提供的必要上下文，不能切换模式。

## 2. 剧情通用

- `世界信息`、`地点与NPC线路`、`入侵与遭遇类型`：仅在开始游戏时建立世界连续性。
- `变量说明`：普通剧情每轮可见的长期事实，不包含模式与爬塔运行态。
- `等级表现形式`：长期成长的叙事尺度。
- `输出格式要求`：剧情正文职责。
- `剧情交接锚点`：初始化、内容变化与遇敌标记的唯一判定入口。

## 3. MVU 数据契约

- `[initvar]不要启用`：保持关闭，只作为 MVU 初始化模板读取。
- `额外模型变量更新格式`：MVU 命令语法与数组/对象写法的唯一权威。
- `变量更新规则`：完整当前快照、普通增量更新和专用事务路由。
- `变量数据结构`：路径形状、生命周期和程序独占字段的唯一权威。
- `卡牌常驻规范`：永久战斗内容的增删与复用边界，不负责初始化、敌人注册或奖励结算的详细格式。

## 4. 战斗内容生成

- `战斗内容生成要求`：效果 DSL、对象字段和可执行性边界的唯一权威。
- `战斗场景生成`：普通剧情遇敌时注册敌人的唯一详细入口。

## 5. 结算与修复

- `战斗结算生成`：胜负后的奖励与持久后果唯一入口。
- `初始战斗内容修复`：初始化内容或玩家自然语言卡牌修复。
- `战斗场景修复`：当前敌人与本场临时内容修复。

## 6. 爬塔专用

- `远征节点协议`：名称为兼容旧导入保留，内容只服务已锁定爬塔模式的扩展后台请求。
- 后台节点条目只由 `[爬塔后台节点生成]` 或 `[爬塔开局馈赠事件]` 激活；普通剧情、常规 MVU 第二轮和战斗操作不会加载它。第一轮短开场由独立的模式入口条目负责。
- 地图、路线、节点状态、难度、奖励可见时机与计分均由程序负责；AI 只补齐当前请求指定的节点内容。

## 7. 末端终检

- 剧情模型最后执行 `剧情交接锚点`。
- MVU 普通更新最后执行 `额外模型变量更新格式`。
- 遇敌、结算与修复分别只执行各自专用条目的终检，不把其他阶段规则拼接进同一轮。

## 维护约束

- 同一字段形状只在 `变量数据结构` 定义一次；其他条目只说明本事务是否可写。
- 同一效果语义只在 `战斗内容生成要求` 定义一次；其他条目引用它，不复制 DSL。
- 技术字段示意只描述数据形状，不提供固定题材、角色、卡牌、敌人或固定数值模板。
- 剧情模式不读取爬塔短叙事协议；爬塔后台请求也不加载剧情正文篇幅规则。
