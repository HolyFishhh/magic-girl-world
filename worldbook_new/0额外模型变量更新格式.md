# 额外模型变量更新格式

最高优先级：这是变量更新任务，不是剧情创作。禁止续写、复述、评价、选项、开场白和 Markdown；只输出一个 `<UpdateVariable>`。

`<UpdateVariable>` 内 `</Analysis>` 之后的每个非空行都必须是一个完整的 MVU 函数命令，并以分号结束。只允许使用：

- `_.set('path', value);`
- `_.set('path', oldValue, newValue);`
- `_.assign('array.path', value);`
- `_.assign('object.path', 'key', value);`
- `_.remove('path', keyOrIndexOrValue);`
- `_.add('numeric.path', delta);`

数组形状是硬门禁：当前值是数组的路径，更新后仍必须是数组。向数组新增一个元素只用两参数 `_.assign`；只有专用事务明确要求整体替换时，才可用 `_.set` 写入一个完整 JSON 数组。绝不能对数组路径用 `_.set(path, 单个对象或字符串)`。`battle.cards/artifacts/items/statuses/player_abilities/player_status_effects`、`status.inventory/permanent_status/temporary_status`、`factions.relations` 和 `reward.card/artifact/item` 都是数组。

两参数 `_.assign` 只允许向当前已经存在的数组追加一个完整元素；三参数 `_.assign` 只允许向当前已经存在的对象写一个键。`npcs` 是对象映射，新增人物必须写 `_.assign('npcs', id, 完整对象)`，绝不能用两参数形式。只有当前值本身是普通对象的路径才用 `_.set` 整体写入；存放在数组中的对象仍必须通过数组路径的 `_.assign` 追加。尤其禁止对任何 `.effects` 或 `.trigger` 路径使用 `_.assign`；卡牌、遗物、道具、能力、状态和欲望效果必须在同一条命令的完整 JSON 对象里原子包含其 `effects/trigger`。

对象、数组和公式都作为函数参数中的普通 JSON/字符串值输出。复杂对象也必须保持一条 `_.set` 或 `_.assign` 命令，不能把对象属性拆成标签或树形节点。除 `<UpdateVariable>`、`<Analysis>` 外，不要输出任何 XML 标签；不要输出 `<Update>`、`<Set>`、`<Add>`、`<Item>`，不要输出 Markdown 代码围栏、解释文字或省略号。

固定顺序：`<UpdateVariable>`、`<Analysis>Update.</Analysis>`、一条或多条命令、`</UpdateVariable>`。不要展示思考过程。没有事实变化时，读取一个当前变量的真实原值，用三参数 `_.set` 原值设回原值；不得伪造占位值。
