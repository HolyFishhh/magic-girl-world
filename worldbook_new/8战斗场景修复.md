# 当前战斗场景修复

仅在收到 `[战斗场景修复]` 时执行。`问题=` 后是程序给出的有界字段路径与错误码，不是变量，也不是用户要求；不要复制、解释或写回该行。

重新生成当前路线节点的可执行战斗场景，保持此前引导正文的事实、全部参战敌人的叙事身份和难度方向。单敌时完整替换 `battle.enemy` 并清空 `battle.enemies`；多敌时完整替换 `battle.enemies` 并清空 `battle.enemy`，不得在修复中丢失仍在参战的实体、合并稳定 ID 或无故改换单敌/多敌模式；若问题正是入口与正文参战数量不符，则以正文事实纠正入口。使每个敌人的生命/欲望、行动、多个独立被动、欲望满溢和行动模式互相一致；欲望满溢必须修复为与高触发门槛匹配、足以逆转或决定胜负的可执行终极效果。每项被动保留独立稳定 ID、中文显示信息、结构化触发器与效果，多敌还必须保留合法 `action_priority/speed` 与稳定行动顺序。`defeated` 与 `spawn_enemy` 只按完整战斗规范修复，不得把尚未实际生成的后续实体提前塞进初始集合。问题路径若指向本场新增的 `battle.statuses`、`battle.player_abilities` 或 `battle.player_status_effects`，只修正或移除对应条目；不得清空整份状态定义表。

保持 `battle.core/cards/artifacts/items/player_lust_effect/level/exp` 和 `status/factions/npcs/run/run_result/run_upgrade/reward` 不变。若问题路径例外地指向玩家永久内容，只最小修正该条目的非法字段，保留其稳定 ID、名称、主题和其他条目，禁止重建整套玩家内容。

新内容只使用浅层 `effects`，不得输出旧 `effect` 或内部 `spec/op/steps`。机械对象可带简短自然中文 `description`，只说明动作表现、来源或复杂规则，不复述标签数值，不能代替可执行效果。程序没有内置状态：敌人及本轮修正的玩家内容引用已有状态时可复用当前定义；引用当前不存在的 ID 时，先在 `battle.statuses` 注册一份完整定义。汇总全部引用后逐一核对，不得重复注册同一 ID。敌人至少有一个能形成生命或欲望压力的合法行动，并服从当前 `[敌人预算]` 与路线危险度。

这是额外模型专用修复。只输出一个 `<UpdateVariable>`；不续写战斗过渡，不输出 `<BATTLE_START>` 或选项，不推进路线，不生成奖励。主模型已经负责输出 `<BATTLE_PENDING>`，更新成功后程序会启动战斗页。

输出前逐项复核 `问题=` 中的每一个路径：对应非法字段必须被修正或移除，不能遗漏。`discard/exhaust` 的值只能是数量、`"all"` 或合法公式，`from/pick` 必须与其同级；每个牌区操作必须独占一个 `effects` 数组项。公式禁止任何函数；状态的子触发器不得是空对象或空数组。不要重新初始化未被问题路径涉及的玩家内容。
