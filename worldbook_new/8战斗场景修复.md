# 当前战斗场景修复

本条是当前敌人与本场临时战斗内容的唯一修复入口，仅在收到 `[战斗场景修复]` 时执行。`问题=` 后是程序给出的有界字段路径与错误码，不是变量，也不是用户要求；不要复制、解释或写回该行。

重新生成当前路线节点的可执行战斗场景，保持此前引导正文的事实、全部参战敌人的叙事身份和难度方向。单敌时完整替换 `battle.enemy` 并清空 `battle.enemies`；多敌时完整替换 `battle.enemies` 并清空 `battle.enemy`，不得在修复中丢失仍在参战的实体、合并稳定 ID 或无故改换单敌/多敌模式；若问题正是入口与正文参战数量不符，则以正文事实纠正入口。使每个敌人的生命/欲望、行动、多个独立被动和行动模式互相一致；只有真实欲望体系才保留或补写欲望满溢。只要生成，满溢通常积累数回合，无论主副轴，兑现都须明显超过普通单卡：以同等回合与费用用于直接输出能取得的累计收益为参照，并计入触发后的持续收益，不能只多一点；不能修成低收益循环、固定小数值或硬编码终结。原描述明确承诺终局时落实对应可执行终局机制，不靠改说明掩盖缺失。每项被动保留独立稳定 ID、中文显示信息、结构化触发器与效果，多敌还必须保留合法 `action_priority/speed` 与稳定行动顺序。`defeated` 与 `spawn_enemy` 只按完整战斗规范修复，不得把尚未实际生成的后续实体提前塞进初始集合。问题路径若指向本场新增的 `battle.statuses`、`battle.player_abilities` 或 `battle.player_status_effects`，只修正或移除对应条目；不得清空整份状态定义表。

保持 `battle.core/cards/artifacts/items/player_lust_effect/level/exp` 和 `status/factions/npcs/run/run_result/run_upgrade/reward` 不变。若问题路径例外地指向玩家永久内容，只最小修正该条目的非法字段，保留其稳定 ID、名称、主题和其他条目，禁止重建整套玩家内容。

新内容只使用浅层 `effects`，不得输出旧 `effect` 或内部 `spec/op/steps`。机械对象可带简短自然中文 `description`，只说明动作表现、来源或复杂规则，不复述标签数值，不能代替可执行效果。程序没有内置状态：敌人及本轮修正的玩家内容引用已有状态时可复用当前定义；引用当前不存在的 ID 时，先在 `battle.statuses` 注册一份完整定义。汇总全部引用后逐一核对，不得重复注册同一 ID。敌人至少有一个能形成生命或欲望压力的合法行动，并服从当前 `[敌人预算]` 与路线危险度。

这是额外模型专用修复。只输出一个 `<UpdateVariable>`；不续写战斗过渡，不输出 `<BATTLE_START>` 或选项，不推进路线，不生成奖励。主模型已经负责输出 `<BATTLE_PENDING>`，更新成功后程序会启动战斗页。

输出前逐项复核 `问题=` 中的每一个路径：对应非法字段必须被修正或移除，不能遗漏。`discard/exhaust` 的值只能是数量、`"all"` 或合法公式，`from/pick` 必须与其同级；每个牌区操作必须独占一个 `effects` 数组项。数值公式的数学函数只允许 `floor/ceil/abs/min/max`；布尔条件仍可使用完整战斗契约公开的条件函数（包括 `event_status_is`），不得删除合法事件条件。禁止未公开函数、对象方法或 JavaScript；状态的子触发器不得是空对象或空数组。不要重新初始化未被问题路径涉及的玩家内容。


### 保护规则的有限修复
保护是敌人能力或供敌人持有的状态定义上的 `protection:{mode:"intercept"|"share_damage",scope:"specific"|"all_allies",target_id?,priority?}`，不是浅层效果操作。只修已定位的错误字段，保留其他合法能力、状态与外观字段。specific 必须精确引用同场敌人实例 id，all_allies 不带 target_id；无效目标不回退。纯持续保护能力可用 `trigger:{on:"passive",effects:{}}`，状态可用空 `triggers:{}`，不得为了过校验伪造格挡、伤害或其他收益。均摊仅分配本次攻击伤害，不改成平均当前生命值。
