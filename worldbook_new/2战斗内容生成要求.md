# AI 战斗内容生成契约

本游戏是 1v1 单机卡牌战斗：只有玩家抽牌、支付能量并打牌；敌人按行动表行动。所有可执行内容必须使用本文件的浅层 JSON；`effect` 字符串和内部 `spec/op/steps` AST 都会被拒绝。

## 通用规则

- ID 稳定且唯一，只用字母、数字、下划线，必须以字母或下划线开头。
- 数值直接写 JSON number，不要写成数字字符串；对象和数组也不得字符串化。
- 每个对象只选 `effects` 新格式；不得同时输出 `effect`。
- 单个或同条件组合优先让 `effects` 直接写一个对象；只有先后依赖、不同条件或不同触发时才写对象数组。不嵌套效果树。
- `damage/heal/block/energy/lust/apply_status/remove_status/draw` 可在同一对象组合，例如 `{"damage":8,"block":5}`。共享 `when/on` 只写一次；需要指定先后时必须拆成数组。
- 默认值不写：常用目标、`stacks:1`、`from:"hand"`、`count:1`、false 布尔字段均省略。
- 卡牌、`creates` 模板、遗物、道具、能力、敌人行动、双方欲望效果和状态都不要输出 `description`；程序直接从已验证的 `effects`、条件、触发器、状态衰减和关键词生成权威说明。战斗/初始化内容引用新状态时在同一消息的 `battle.statuses` 注册；奖励候选使用下文的同级 `status`。
- 运行时会在战斗开始前递归预检；未知字段、变量、状态、重复 ID、非法选择器、空效果或错误类型都会按字段路径拒绝。

## 浅层 effects

常用写法及默认目标：

| 写法 | 含义 |
| --- | --- |
| `{"damage":8}` | 对对方造成 8 点生命伤害 |
| `{"damage":4,"hits":3}` | 对对方依次造成 3 次 4 点伤害 |
| `{"heal":5}` | 自身恢复 5 点生命 |
| `{"block":6}` | 自身获得 6 点格挡 |
| `{"energy":1}` | 自身获得 1 点能量 |
| `{"lust":4}` | 对方欲望增加 4 |
| `{"set_hp":20}` | 自身生命设为 20 |
| `{"apply_status":"weak","stacks":2}` | 对方获得 2 层 weak |
| `{"remove_status":"weak"}` | 移除对方 weak |
| `{"draw":2}` | 玩家抽 2 张牌 |
| `{"scry":3}` | 查看抽牌堆顶 3 张牌，可将任意张置入弃牌堆 |
| `{"seek":1}` | 从抽牌堆选择 1 张牌加入手牌 |

非默认目标添加同级 `"to":"self"` 或 `"to":"opponent"`。`remove_status` 也接受 `all/buffs/debuffs`。

`effects` 的推荐形状：

```json
"effects":{"damage":8}
"effects":{"damage":8,"block":5}
"effects":{"damage":6,"apply_status":"weak","stacks":2}
```

组合对象按固定顺序展开，不依赖 JSON 字段排列。`hits` 只与单独的 `damage` 同级使用，范围 1-20；每击分别结算格挡和触发器。若后一个效果必须读取前一个效果改变后的状态，改写为数组；牌区操作、`modify/add_card/narrate/set_*` 也保持单独对象。

### 公式与条件

数值可写安全公式字符串；允许 `+ - * /`、括号、比较、`&& || !` 和三元表达式，不允许函数调用或 JavaScript。

可用变量：

- `spent_energy`、`turn_number`、`cards_played_this_turn`
- `attacks_played_this_turn`、`skills_played_this_turn`
- `self.hp/max_hp/lust/max_lust/energy/max_energy/block`
- `self.hand_size/draw_pile_size/discard_pile_size/exhaust_pile_size`
- `opponent.hp/max_hp/lust/max_lust/energy/max_energy/block`
- `self.status.<id>.stacks`、`opponent.status.<id>.stacks`
- 仅状态触发器额外允许 `stacks`，表示该状态当前层数

`turn_number` 从 1 开始；三种本回合出牌计数都包含当前正在结算的牌，并在下一玩家回合归零。例如 `{"damage":"turn_number * 2"}` 随回合成长，`{"damage":"attacks_played_this_turn * 3"}` 是攻击连击终结技。

X 费牌将 `cost` 写为 `"energy"`，用 `spent_energy` 表示本次实际支付值：

```json
"effects":[
  {"damage":"spent_energy * 4"},
  {"block":1,"when":"spent_energy == 0"}
]
```

复杂分支用多个带同级 `when` 的效果；单个数值二选一可用三元公式。不要生成嵌套条件树。

### 牌区操作

```json
{"scry":3}
{"seek":1}
{"discard":2}
{"discard":1,"pick":"choose"}
{"exhaust":"all","from":"discard"}
{"recover":1,"from":"discard","pick":"choose"}
{"reduce_cost":1,"count":2,"pick":"choose"}
{"copy":1,"from":"draw","pick":"random"}
{"double":1,"pick":"choose"}
```

`from` 可用 `hand/draw/discard/all`，默认 `hand`；`pick` 可用 `random/choose/left/right/all`。`left/right` 仅适用于手牌，`from:"all"` 必须搭配 `pick:"all"`。跨多个牌区时写多个效果对象。

`seek` 只写数量，不搭配 `from/pick/count`；玩家从整个抽牌堆选择该数量张原卡加入手牌，牌堆不足或手牌空位不足时按可用数量处理。它不触发 `on_draw`，并受 10 张手牌上限约束。

`recover` 的 `from` 仅用 `discard/exhaust`，`pick` 仅用 `random/choose/all`；全部取回写 `recover:"all",pick:"all"`。取回不触发 `on_draw`，手牌上限 10。

`scry` 只写查看数量，不搭配 `from/pick/count`。它只检视当前抽牌堆顶部，玩家可选择 0 到该数量张置入弃牌堆；不抽牌，也不触发 `on_draw/on_discard`。

### 持续修饰符

修饰符只用于 `passive` 能力/遗物或状态 `hold`：

```json
{"modify":"damage","add":2}
{"modify":"damage_taken","multiply":1.5}
{"modify":"block","add":"stacks * 3"}
```

`modify` 可用 `damage/damage_taken/lust/lust_taken/heal/block`；每项恰好使用 `add/subtract/multiply/divide/set` 之一。修饰值只用数字，状态 `hold` 中可额外用 `stacks` 算式；修饰符不使用 `when/on`。

## 卡牌

卡牌最小结构：

```json
{"id":"moon_slash","name":"月轮斩","emoji":"🌙","type":"Attack","rarity":"Common","cost":1,"quantity":5,"effects":{"damage":8}}
```

- `type`：`Attack/Skill/Power/Event/Curse`。
- `rarity`：`Common/Uncommon/Rare/Epic/Legendary/Corrupt`。
- 普通费用是 0-3 的整数；X 费使用 `"energy"`。Curse 不写 `cost` 且无法主动打出。
- `innate:true` 开战时优先进入起始手牌；`retain:true` 跨回合保留；`exhaust:true` 打出后消耗；`ethereal:true` 未打出则回合末消耗。Power 自动视为 `exhaust:true`。
- `discard_effects` 与 `effects` 相同：单个/组合效果写对象，需要分步时才写数组。
- Event 的 `effects` 必须且只能是一个顶层 `{"narrate":"叙事"}`；使用后结束战斗并返回剧情。其他入口禁止 `narrate`。

Power 把主要触发器写在卡牌同级，只写一次：

```json
{"id":"moon_guard","name":"月相守护","type":"Power","rarity":"Rare","cost":1,"quantity":1,"trigger":"turn_start","effects":[{"block":4},{"draw":1,"when":"self.hp < self.max_hp / 2"}]}
```

第二种触发时机才在例外效果上写 `on`。Power 可用触发器：`ability_gain/turn_start/turn_end/card_played/attack_played/skill_played/power_played/on_discard/on_exhaust/on_draw/on_shuffle/take_damage/take_heal/deal_damage/deal_heal/lust_increase/lust_decrease/deal_lust_increase/deal_lust_decrease/gain_buff/gain_debuff/lose_buff/lose_debuff/enemy_gain_buff/enemy_gain_debuff/enemy_lose_buff/enemy_lose_debuff/gain_block/lose_block`。`card_played` 响应任意可打出的牌；只响应一种牌型时改用 `attack_played/skill_played/power_played`，不要增加嵌套对象。每次打牌先结算通用事件，再结算对应牌型事件；每个事件内能力先于遗物。`on_exhaust` 在每张牌实际进入消耗堆后触发，覆盖打出后消耗、空灵和效果选择消耗。`on_draw` 在牌真正进入手牌后逐张触发；`on_shuffle` 在弃牌堆回洗并进入抽牌堆后触发一次。起始手牌不触发这两个事件。为避免无限循环，`on_draw/on_shuffle` 效果中不得再次写 `draw`。

动态插牌引用同张卡的 `creates` 模板，禁止把卡牌 JSON 塞进字符串：

```json
{"id":"spark_forge","name":"火花锻造","type":"Skill","rarity":"Uncommon","cost":1,"quantity":1,"effects":{"add_card":"spark","count":2},"creates":[{"id":"spark","name":"火花","type":"Attack","rarity":"Common","cost":0,"effects":{"damage":3},"exhaust":true}]}
```

`add_card` 的 `to` 只接受 `hand/deck`，默认 `hand`。模板 ID 唯一，不得循环生成，不需要 `quantity`。

## 其他战斗内容

这些入口也只生成 `effects`：

```json
{"id":"star_charm","name":"星辉护符","emoji":"⭐","rarity":"Common","trigger":"battle_start","effects":{"block":3}}
{"id":"blade_echo","name":"刃光回声","emoji":"⚔️","rarity":"Uncommon","trigger":"attack_played","effects":{"block":1}}
{"id":"tonic","name":"微光药剂","emoji":"🧪","count":1,"effects":{"heal":10}}
{"id":"battle_focus","name":"战斗专注","trigger":"turn_start","effects":{"energy":1}}
{"name":"重击","weight":2,"effects":{"damage":9}}
{"name":"月蚀反击","effects":{"damage":8}}
```

- 遗物与能力必须有同级 `trigger`。额外支持 `battle_start` 与 `passive`；`passive` 只放修饰符。
- 道具、敌人行动、双方欲望满溢效果不写 `trigger`，不得注册延迟触发。
- 遗物稀有度：`Common/Uncommon/Rare/Boss/ENS`。道具使用后 `count-1`。
- 敌人行动的 `damage` 默认伤害玩家；敌人来源中的 `self` 始终指敌人，`opponent` 指玩家。

## 状态定义

```json
{"id":"bleed","name":"流血","emoji":"🩸","type":"debuff","stacks_change":-1,"maxStacks":12,"triggers":{"tick":{"damage":"stacks","to":"self"}}}
```

- `type` 只用 `buff/debuff/neutral`。
- `triggers` 只允许 `apply/stack/tick/remove/hold`；值遵循同一浅层效果对象/数组规则。
- `apply` 首次施加触发；`stack` 实际增加层数时触发；`tick` 回合末触发；`remove` 移除时触发；`hold` 只放持续修饰符。
- `stacks_change` 可用数字、`"x0.5"`、`"reset"`、`"keep"`；`maxStacks` 是正数。
- 需要让状态持有者无法行动时，在状态同级写 `"stun":true`。谨慎设置衰减，禁止永久眩晕。
- 新状态只使用结构化效果，因此不写 `description`；字符串触发器会被拒绝。
- 奖励候选若引用一个尚未注册的新状态，可在候选同级附加 `"status":{完整状态定义}`。只在确有新状态时写；程序仅在该候选被选择后原子注册状态，并从永久卡牌/遗物/道具中移除此辅助字段。

## 设计与完整性

- 初始牌组总 `quantity` 至少 10，必须有稳定的攻击、防御与核心联动，不能依赖抽到唯一一张牌才可行动。
- 每套构筑至少有一种可靠胜利手段、一种防御手段；欲望构筑必须能在 1-3 次满溢内产生足以推进胜利的收益。
- 复杂卡优先使用一个组合对象，确有顺序/条件差异时控制在 2-4 个数组项；只有确有必要才使用 Power、状态或动态插牌。
- 卡牌复杂度随稀有度增长：Common 通常 1 个主要效果，Uncommon 1-2 个，Rare/Epic 2-3 个，Legendary 最多 4 个；不要靠堆字段伪装稀有度。
- 敌人至少有一个可执行行动；攻击、防御和机制强度要与玩家等级、卡组恢复与防御能力匹配，避免无解锁死与无限战斗。
- `[构筑建议] need=... synergy=... roles=...` 已由程序分析当前牌组。`roles` 可能带有程序给出的括号方向，例如 `补短板(防御),强联动(状态:ember_mark),转方向`；奖励或商店的三张卡依次满足三个 `roles`，围绕 `need/synergy` 设计但不要复制、解释或写回该行；无 `synergy` 时程序会省略它。
- 同批候选服从 `[构筑建议] roles` 并有明确叙事身份。机制或数值相同可以接受；不同对象使用不同稳定 ID，同一 ID 不得改写规则。
