# 初始战斗内容修复

本条是初始化玩家战斗内容和玩家自然语言卡牌调整的唯一修复入口，仅在收到 `[战斗内容修复]` 或 `[玩家自然语言卡牌修复]` 时执行。

收到 `[玩家自然语言卡牌修复]` 时，`用户要求=` 后的 JSON 字符串是玩家用自然语言提出的卡牌调整要求。读取当前完整 `battle.cards`，只对要求涉及的卡牌做最小增量修改；未被要求的卡牌保持原样，所有非卡牌变量保持原样。除非玩家明确要求整套重做，否则禁止重新初始化或重建整套卡组。只输出一个 `<UpdateVariable>`，不续写剧情、不输出选项或新对话内容。完成这一分支后不要继续执行下方的程序报错修复规则。

收到 `[战斗内容修复]` 时，`问题=` 后是程序给出的字段路径与错误码，不是新变量；按路径修正，不要复制、解释或写回该行。

按 `问题=` 给出的路径最小修复与当前角色身份、职业和既有开场设定一致的初始战斗内容，只允许修改：

- `battle.core.emoji/hp/max_hp/lust/max_lust/card_removal_count/resources`、`battle.level`、`battle.exp`
- `battle.cards/artifacts/items/statuses`
- `battle.player_abilities/player_status_effects/player_lust_effect`

保持剧情事实和 `status/factions/npcs` 不变；禁止修改 `run/run_result/run_upgrade/reward/enemy`，不生成 Option 或 `<BATTLE_START>`。这是 MVU 额外模型的原楼层修复，只输出一个 `<UpdateVariable>`，不要续写剧情或创建新的对话内容。

输出前逐项复核 `问题=` 中的每一个路径：对应非法字段必须被修正或移除，不能遗漏。`discard/exhaust` 的值只能是数量、`"all"` 或合法公式，`from/pick` 必须与其同级；每个牌区操作必须独占一个 `effects` 数组项。数值公式的数学函数只允许 `floor/ceil/abs/min/max`；布尔条件仍可使用完整战斗契约公开的条件函数（包括 `event_status_is`），不得删除合法事件条件。禁止未公开函数、对象方法或 JavaScript；状态的子触发器不得是空对象或空数组。不要为了修复单项错误重新初始化未被问题路径涉及的内容。

修复时优先按下面的字段形状纠正模型常见偏差；这些只是语法边界，不限定题材、名称、数值或机制选择：

- 状态生命周期键 `apply/stack/tick/remove/hold/threshold_execute` 与事件键 `battle_start/ability_gain/turn_start/turn_end/card_played/attack_played/skill_played/power_played/on_discard/on_exhaust/on_draw/on_shuffle/take_damage/take_heal/deal_damage/deal_heal/lust_increase/lust_decrease/deal_lust_increase/deal_lust_decrease/gain_buff/gain_debuff/lose_buff/lose_debuff/enemy_gain_buff/enemy_gain_debuff/enemy_lose_buff/enemy_lose_debuff/gain_block/lose_block/defeated` 都直接写非空浅层效果对象或数组，禁止再包一层 `effects`、`{on,effects}` 或 `{when:X,effects:...}`。若原值是 `{when:X,effects:[A,B]}`，必须机械改成 `[{...A,when:X},{...B,when:X}]`；单个 A 改成 `{...A,when:X}`，A/B 已有条件 Y 时合并为 `when:"(X) && (Y)"`。原操作、数值、目标与条件都必须保留，不能只留下 `when`，也不能删除操作后保留空壳。
- 公式中的 `has_status/has_buff/has_debuff/has_neutral` 是无参数布尔字段，不是函数。若原条件写 `self.has_status('状态ID')` 或 `opponent.has_status('状态ID')`，分别机械改成 `self.status.状态ID.stacks > 0` 或 `opponent.status.状态ID.stacks > 0`；只有判断任意一种状态是否存在时才直接使用不带括号的 `self.has_status` 或 `opponent.has_status`。
- `replay_current` 只属于当前正在结算的非 Power、非 Event 卡牌主效果，状态事件没有可重放的当前牌。若某状态事件中的非法 `replay_current` 原意是“持有状态时，下一张或前 N 张某类型牌额外完整结算”，必须保留重放次数与牌型，删除该事件子触发器，在同一状态的 `triggers.hold` 写 `{card_rule:"replay",card_type:"对应牌型",limit:N,extra:原重放次数}`，并按原持续时间保留或修正 `stacks_change`；一次性状态使用 `stacks_change:"reset"`。不得改成增伤、重复单段伤害、零值或纯描述。
- 若原意是“当前这张非 Power、非 Event 卡在原效果结束后免费再次完整结算 N 次”，必须保留原效果，并把错误的 `{replay:true|N,when?...}` 等价迁移为独立数组项 `{replay_current:N,when?...}`。若 `replay_current` 写成“条件 ? N : 0”三元式，把条件只保留在 `when`，并把 `replay_current` 改为正数 N，不能重复两份条件。费用仍只支付一次，重放会正常触发出牌联动；禁止删掉重放、改成重复伤害、只提高伤害数值，或改写成影响后续卡牌的 `double/patch_card/card_rule`。`replay_current` 不能进入触发器、弃牌效果、状态、遗物、能力、敌人、召唤或预约效果；若错误内容位于这些脱离当前牌的入口，必须根据原描述把机制迁回实际卡牌主效果，而不是留下不可执行占位。
- 状态的持续数值修饰只能放在 `hold` 中，使用同级的 `modify` 与唯一运算字段，例如 `{"modify":"damage","add":2}`；不得在 `tick` 中发明内部修饰器字段。`tick` 只用于围绕持有者行动实际执行的浅层效果；状态根 `tick_timing` 只能为 `before_action` 或 `after_action`，省略默认为前者。它不是 `turn_start`/`turn_end`，不额外触发那些事件；`stacks_change` 仍只在持有者回合末衰减一次。
- 若非法 `hold` 原文是 `{on:"事件名",effects:原效果}` 或包含这种数组项，它表达的是持有状态期间监听真实战斗事件。保留原事件、效果、数值、目标和状态寿命，把原效果完整移动到同一状态的 `triggers.事件名`；例如 `on:"attack_played"` 改为同级 `attack_played:{...}`。禁止删成空 `hold`，也禁止改成不等价的伤害、成长或零值占位。事件型状态只在持有期间工作，省略 `to` 时以精确持有者为 `self`，并可读取裸 `stacks`；它不接受 `scope/ordinal/n/event` 等筛选字段。
- `damage_modifier/damage_taken_modifier/lust_damage_modifier/lust_damage_taken_modifier/heal_modifier/block_modifier` 不是卡牌、状态触发器或其他 `effects` 的公开操作键；它们只允许出现在召唤定义自己的 `modifiers` 映射中。卡牌本次造成伤害就直接写 `damage`；需要持续改变实体数值时，先注册合法状态并让卡牌用 `apply_status` 施加，实际 `modify` 规则写进该状态的 `triggers.hold`。
- `apply_status/remove_status` 的值直接写稳定状态 ID 字符串，层数和目标写在同级：`{apply_status:"状态ID",stacks:2,to:"opponent"}`、`{remove_status:"状态ID",to:"self"}`；被引用 ID 必须已有合法定义或在本次修复中先注册。
- `hits` 只能和 `damage` 写在同一个浅层效果项，不能单独占一个数组项。`Curse` 牌必须省略 `cost`，不能用零费用代替。若它只是不可打出并占据手牌的纯死牌，可同时省略 `effects`；遇到非法 `narrate` 时删除该效果并保留叙事到 `description`，不要编造伤害、零值或无关惩罚。有真实抽取、弃牌或回合末后果的 Curse 仍必须保留并修正对应可执行效果。
- `copy/double` 的值直接写数量或 `"all"`，`from/pick` 与过滤条件放在同一效果项的同级；禁止把选择器对象嵌进操作值。`add_card/ensure_card` 的值直接写当前内容对象 `creates` 中已登记的模板 ID 字符串，`to/count` 与操作同级；缺少模板时依据原机制补齐完整模板及其依赖，不能直接引用永久卡牌 ID，也不能靠删除生成操作通过校验。
- `set_hp/set_lust/set_energy/set_block` 的值直接是数值或合法公式，禁止包装成 `formula/value/amount` 对象。
- `scry/seek` 只写数量，不附加 `from/pick`；`discard/exhaust/recover` 才按各自契约使用同级牌区选择字段。
- 自定义 `resource/set_resource` 只能引用 `battle.core.resources` 中已完整注册的 ID；缺少资源时依据原机制补齐定义并保留实际获得、消耗与刷新语义；不得擅自改成能量或删除资源效果，禁止留下未注册引用。
- 每个道具必须有非空 `effects`；遗物和独立能力必须有合法非空 `trigger.on/trigger.effects`；双方欲望效果必须有非空 `effects`，不能只留下名称或描述。

已有且未被问题路径指出的合法卡牌、状态、遗物和道具必须保留，禁止每次修复都重建整套内容。只有卡组为空或卡组结构本身无法执行时才完整替换 `battle.cards`；重建时至少生成一个真实卡牌定义，不对定义数或总 `quantity` 设质量门槛。卡组总量、基础能量下可打出率、传统胜利手段、遗物、道具、玩家欲望效果、攻守恢复比例和程序评分都不是结构问题，绝不能因此触发修复、删牌或重建。所有卡牌只能写入 `battle.cards`；`battle.player_abilities` 只允许带 `trigger` 的本场被动能力。新内容只使用浅层 `effects`，不得输出旧 `effect` 或内部 AST。可以保留或补写简短的中文叙事描述，但不能让描述代替效果，也不能暴露 ID 或公式。

白名单内的预设状态自动展开，其他状态须先完整定义后引用。修复前汇总本轮修改内容引用的全部状态 ID；已有合法定义直接复用，只有缺失或被问题路径指出的定义才新增或修正。若不同内容复用同一状态，只共享该 ID 和一份定义，不得重复定义、生成未引用的备用状态或留下无定义引用。未明确要求“状态构筑”不代表已创作的状态机制可以删除。只移除确实无引用且无实际用途的冗余定义；被真实机制使用的定义须保持语义修正。无法等价修复时保留失败，不返回削减玩法的成功更新。


### 保护规则的有限修复
保护是敌人能力或供敌人持有的状态定义上的 `protection:{mode:"intercept"|"share_damage",scope:"specific"|"all_allies",target_id?,priority?}`，不是浅层效果操作。只修已定位的错误字段，保留其他合法能力、状态与外观字段。specific 必须精确引用同场敌人实例 id，all_allies 不带 target_id；无效目标不回退。纯持续保护能力可用 `trigger:{on:"passive",effects:{}}`，状态可用空 `triggers:{}`，不得为了过校验伪造格挡、伤害或其他收益。均摊仅分配本次攻击伤害，不改成平均当前生命值。
