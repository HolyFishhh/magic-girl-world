# 初始战斗内容修复

本条是初始化玩家战斗内容和玩家自然语言卡牌调整的唯一修复入口，仅在收到 `[战斗内容修复]` 或 `[玩家自然语言卡牌修复]` 时执行。

收到 `[玩家自然语言卡牌修复]` 时，`用户要求=` 后的 JSON 字符串是玩家用自然语言提出的卡牌调整要求。读取当前完整 `battle.cards`，只对要求涉及的卡牌做最小增量修改；未被要求的卡牌保持原样，所有非卡牌变量保持原样。除非玩家明确要求整套重做，否则禁止重新初始化或重建整套卡组。只输出一个 `<UpdateVariable>`，不续写剧情、不输出选项或新对话内容。完成这一分支后不要继续执行下方的程序报错修复规则。

收到 `[战斗内容修复]` 时，`问题=` 后是程序给出的字段路径与错误码，不是新变量；按路径修正，不要复制、解释或写回该行。

按 `问题=` 给出的路径最小修复与当前角色身份、职业和既有开场设定一致的初始战斗内容，只允许修改：

- `battle.core.emoji/hp/max_hp/lust/max_lust/card_removal_count/resources`、`battle.level`、`battle.exp`
- `battle.cards/artifacts/items/statuses`
- `battle.player_abilities/player_status_effects/player_lust_effect`

保持剧情事实和 `status/factions/npcs` 不变；禁止修改 `run/run_result/run_upgrade/reward/enemy`，不生成 Option 或 `<BATTLE_START>`。这是 MVU 额外模型的原楼层修复，只输出一个 `<UpdateVariable>`，不要续写剧情或创建新的对话内容。

输出前逐项复核 `问题=` 中的每一个路径：对应非法字段必须被修正或移除，不能遗漏。`discard/exhaust` 的值只能是数量、`"all"` 或合法公式，`from/pick` 必须与其同级；每个牌区操作必须独占一个 `effects` 数组项。公式禁止任何函数；状态的子触发器不得是空对象或空数组。不要为了修复单项错误重新初始化未被问题路径涉及的内容。

修复时优先按下面的字段形状纠正模型常见偏差；这些只是语法边界，不限定题材、名称、数值或机制选择：

- 状态 `triggers` 的 `apply/stack/tick/remove/hold` 值直接写非空浅层效果对象或数组，禁止再包一层 `effects`；没有实际触发效果就删除该子触发器，不得保留空壳。
- 状态的持续数值修饰只能放在 `hold` 中，使用同级的 `modify` 与唯一运算字段，例如 `{"modify":"damage","add":2}`；不得在 `tick` 中发明内部修饰器字段。`tick` 只用于每回合实际执行的浅层效果。
- `damage_modifier/damage_taken_modifier/lust_damage_modifier/lust_damage_taken_modifier/heal_modifier/block_modifier` 不是卡牌、状态触发器或其他 `effects` 的公开操作键；它们只允许出现在召唤定义自己的 `modifiers` 映射中。卡牌本次造成伤害就直接写 `damage`；需要持续改变实体数值时，先注册合法状态并让卡牌用 `apply_status` 施加，实际 `modify` 规则写进该状态的 `triggers.hold`。
- `apply_status/remove_status` 的值是含稳定 `id` 的状态操作对象，层数和目标放在这个对象内；被引用 ID 必须已有合法定义或在本次修复中先注册。
- `hits` 只能和 `damage` 写在同一个浅层效果项，不能单独占一个数组项。`Curse` 牌必须省略 `cost`，不能用零费用代替。
- `copy/double` 的值直接写数量或 `"all"`，`from/pick` 与过滤条件放在同一效果项的同级；禁止把选择器对象嵌进操作值。`add_card/ensure_card` 的值直接写当前内容对象 `creates` 中已登记的模板 ID 字符串，`to/count` 与操作同级；没有合法模板时删除该引用或补齐模板，不能直接引用永久卡牌 ID。
- `set_hp/set_lust/set_energy/set_block` 的值直接是数值或合法公式，禁止包装成 `formula/value/amount` 对象。
- `scry/seek` 只写数量，不附加 `from/pick`；`discard/exhaust/recover` 才按各自契约使用同级牌区选择字段。
- 自定义 `resource/set_resource` 只能引用 `battle.core.resources` 中已完整注册的 ID；不打算补全资源定义时就改用已有能量或删除该资源效果，禁止留下未注册引用。
- 每个道具必须有非空 `effects`；遗物和独立能力必须有合法非空 `trigger.on/trigger.effects`；双方欲望效果必须有非空 `effects`，不能只留下名称或描述。

已有且未被问题路径指出的合法卡牌、状态、遗物和道具必须保留，禁止每次修复都重建整套内容。只有卡组本身无效时才完整替换 `battle.cards`；重建空数组时通常使用 3-5 个定义、总 `quantity` 至少 10，不设总量上限，并可一次 `_.set` 写入完整数组。卡组总量超过 13 不是问题路径，绝不能因此触发修复、删牌或重建。所有卡牌只能写入 `battle.cards`；`battle.player_abilities` 只允许带 `trigger` 的本场被动能力。新内容只使用浅层 `effects`，不得输出旧 `effect` 或内部 AST。可以保留或补写简短的中文叙事描述，但不能让描述代替效果，也不能暴露 ID 或公式。修复后必须有基础 3 能量可打出的牌、稳定胜利手段、至少一个遗物、至少一个道具和足以逆转或决定战局的玩家欲望满溢终极效果；攻守与恢复比例由既有构筑决定，不得因修复擅自改造。

程序没有内置状态。修复前汇总本轮修改内容引用的全部状态 ID；已有合法定义直接复用，只有缺失或被问题路径指出的定义才新增或修正。若不同内容复用同一状态，只共享该 ID 和一份定义，不得重复定义、生成未引用的备用状态或留下无定义引用。开局设定没有明确要求状态构筑时，若非法状态只由本轮非法内容引用，优先同时移除引用与无用定义，不要为修复自行扩张状态体系。
