# 初始战斗内容修复

仅在收到 `[战斗内容修复]` 时执行。`问题=` 后是程序给出的字段路径与错误码，不是新变量；按路径修正，不要复制、解释或写回该行。

按 `问题=` 给出的路径最小修复与当前角色身份、职业和既有开场设定一致的初始战斗内容，只允许修改：

- `battle.core.emoji/hp/max_hp/lust/max_lust/card_removal_count`、`battle.level`、`battle.exp`
- `battle.cards/artifacts/items/statuses`
- `battle.player_abilities/player_status_effects/player_lust_effect`

保持剧情事实和 `status/factions/npcs` 不变；禁止修改 `run/run_result/run_upgrade/reward/enemy`，不生成 Option 或 `<BATTLE_START>`。这是 MVU 额外模型的原楼层修复，只输出一个 `<UpdateVariable>`，不要续写剧情或创建新的对话内容。

输出前逐项复核 `问题=` 中的每一个路径：对应非法字段必须被修正或移除，不能遗漏。`discard/exhaust` 的值只能是数量、`"all"` 或合法公式，`from/pick` 必须与其同级；每个牌区操作必须独占一个 `effects` 数组项。公式禁止任何函数；状态的子触发器不得是空对象或空数组。不要为了修复单项错误重新初始化未被问题路径涉及的内容。

已有且未被问题路径指出的合法卡牌、状态、遗物和道具必须保留，禁止每次修复都重建整套内容。只有卡组本身无效时才完整替换 `battle.cards`；重建空数组时通常使用 3-5 个定义、总 `quantity` 至少 10，不设总量上限，并可一次 `_.set` 写入完整数组。卡组总量超过 13 不是问题路径，绝不能因此触发修复、删牌或重建。所有卡牌只能写入 `battle.cards`；`battle.player_abilities` 只允许带 `trigger` 的本场被动能力。新内容只使用浅层 `effects`，不得输出旧 `effect` 或内部 AST。可以保留或补写简短的中文叙事描述，但不能让描述代替效果，也不能暴露 ID 或公式。修复后必须有基础 3 能量可打出的牌、稳定胜利手段、至少一个遗物、至少一个道具和玩家欲望满溢效果；攻守与恢复比例由既有构筑决定，不得因修复擅自改造。

程序没有内置状态。修复前汇总本轮修改内容引用的全部状态 ID；已有合法定义直接复用，只有缺失或被问题路径指出的定义才新增或修正。若不同内容复用同一状态，只共享该 ID 和一份定义，不得重复定义、生成未引用的备用状态或留下无定义引用。
