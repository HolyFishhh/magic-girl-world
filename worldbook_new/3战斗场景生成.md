# 战斗数据注册

只有主模型已经描写完整敌人并以 `<BATTLE_PENDING>` 交接时，才在额外模型解析阶段使用本格式。以主模型的敌人描述为唯一叙事依据，注册完整敌人与本场临时内容。只输出变量更新：

```text
<UpdateVariable>
  <Analysis>Brief battle setup.</Analysis>
  ...完整的 battle.enemy 更新命令...
</UpdateVariable>
```

不要续写剧情，不要输出 `<BATTLE_PENDING>`、`<BATTLE_START>` 或选项。更新成功后，卡内运行时会把主模型的待注册标记转换为战斗启动标记；如果数据无效则保持原文并等待修复。

## 敌人对象

`battle.enemy` 每场都要完整设置，不依赖上一场残留：

```json
{
  "name":"镜影魔女",
  "emoji":"🪞",
  "max_hp":60,
  "hp":60,
  "max_lust":100,
  "lust":0,
  "description":"由破碎镜面聚成的魔女。",
  "actions":[
    {"name":"裂光","weight":3,"effects":{"damage":8}},
    {"name":"镜壳","weight":2,"effects":{"block":7}}
  ],
  "abilities":[
    {"id":"mirror_rage","name":"镜怒","trigger":"passive","effects":{"modify":"damage","add":2}}
  ],
  "status_effects":[],
  "lust_effect":{"name":"镜面反噬","effects":{"damage":6}},
  "action_mode":"probability",
  "action_config":{"probability":{"裂光":3,"镜壳":2}}
}
```

- 对象中的所有可执行内容都使用浅层 `effects`，不得生成旧 `effect` 字符串。
- `actions`、`abilities`、`lust_effect` 不写 `description`；程序从结构化规则生成显示说明。敌人对象本身的剧情 `description` 保留。
- `actions` 至少一个，名称各自唯一；`weight` 为大于 0 的有限数。
- `abilities` 可选，结构与玩家能力相同；`status_effects` 的 ID 必须已在 `battle.statuses` 注册。
- `lust_effect` 表示敌人使玩家欲望满溢后的效果；敌人自己欲望满溢触发玩家的 `battle.player_lust_effect`。
- 当前生命/欲望在 `0..max` 内，最大值大于 0。

## 行动模式

- `random`：从行动表随机选择，无需配置。
- `probability`：`action_config.probability` 用行动名称映射正权重。
- `sequence`：`action_config.sequence` 是非空行动名称数组。
- `sequence_then_probability`：配置中同时提供 `sequence` 和 `probability`，先走完顺序再按权重选择。

配置中的名称必须精确匹配 `actions[].name`；写错会在启动前按路径报错，不会静默退化。

## 难度与可玩性

- 路线标记中的 `kind` 决定战斗级别：`battle` 使用普通强度，`elite` 增加一个清晰机制和更高收益压力，`boss` 使用阶段性或构筑检验机制；不要忽略节点类型。
- `[构筑摘要] deck=... atk=... def=... heal=... draw=... energy=... hp=...` 是程序估算的一手牌预算，只用于调整敌人压力。不要复制、解释或写回它；普通敌人的单轮压力应让当前构筑有应对空间，精英/Boss 可要求明确取舍，但避免无解首轮爆发和只会拖长回合的高血量。
- `[敌人预算] hp=A..B hit=C..D` 已由程序完成数值估算。通常让 `max_hp` 落在 A..B、常规伤害行动落在 C..D；可设计一项有清晰预告与应对方法的更强行动。不要自行重算预算，也不要复制或写回该行。
- 结合玩家等级、当前生命、卡组伤害/防御/恢复、遗物与状态设计，不只按等级机械放大生命。
- 同级普通敌人通常 40-90 HP；精英/Boss 可更高并加入清晰机制。实力差距极大时才使用夸张数值。
- 敌人至少有一种对玩家形成压力的行动；也必须留出可应对窗口，禁止永久眩晕、无限治疗或玩家无法突破的锁死循环。
- 若机制引用新状态，必须在同一更新中先完整注册 `battle.statuses`。
- 当前战斗不得改写永久 `battle.cards/artifacts/items/player_lust_effect` 或成长数据；只生成敌人、新状态定义和确有必要的本场临时玩家能力/状态。永久成长只通过奖励、商店或营火事务进入。
- 敌人可以是非物理对象，如噩梦、欲望或精神投影。
